# Chiplet 背景知识（精简版）

## 核心结论

- Chiplet CPU 的关键问题不是封装形式本身，而是局部性：本地 `L3` 和本地内存访问更快，跨 `CCD/CCX` 或跨 socket 访问更慢，因此对 LLM 推理来说，本质上是更细粒度的 `NUMA` 问题。
- 相对单片架构，Chiplet 牺牲了一部分统一访问特性，换来了更好的可扩展性和良率。
- 性能通常在两件事之间权衡：一是把线程集中到更少的 chiplet 以获得更低通信延迟，二是把线程分散到更多 chiplet 以获得更大的聚合 `L3` 容量。

## AMD 术语

- `CCD`：计算模块，包含核心和 `L3`，不包含内存控制器或 `PCIe` 控制器。
- `CCX`：`CCD` 内部的逻辑单元。
  - `Zen 2`：通常 `1 CCD = 2 CCX`
  - `Zen 3/4`：通常 `1 CCD = 1 CCX`
- `IOD`：I/O Die，包含内存控制器、`PCIe` 和路由逻辑。
- `Infinity Fabric`：连接 `CCD` 和 `IOD` 的高速互联；跨 chiplet 访问要经过它。

## 调度和计数器视角

- `L1/L2` 是核心私有资源；线程迁移会带来冷缓存。
- `L3` 主要按 `CCD/CCX` 共享；访问本地 `L3` 更快，跨 chiplet `L3` 更慢。
- `DRAM` 虽然物理上挂在 `IOD`，但系统仍需要按 `NUMA` 处理局部性和拥塞。
- `Zen 5` 的 `L3` 更接近受害者缓存（victim `L3`）；同一份数据通常不会同时稳定驻留在 `L2` 和 `L3`。
- `L3PMCx04` 等按 `CCX` 层级统计时，命中其他 `CCX` 的 `L3` 也可能被记作 `L3 miss`，解释指标时要谨慎。

## 本机事实

- 平台：`2 x AMD EPYC 9745 128-Core Processor`
- 当前经验基线：`16` 个物理核心共享约 `32 MiB` 本地 `L3`，每个 CPU 有 `8` 个 `CCD`
- 系统信息可用 `AMDuProfCLI info --system` 查看

## 对 LLM 推理的启发

- `Decode` 阶段通常更容易受内存带宽、`L3` 局部性和线程放置影响。
- 只按 `NUMA` 均匀切分进程/线程不一定最优，因为更下层还有 `CCD/CCX/L3` 竞争。
- 小工作集更适合集中放置；大工作集或高 `miss` 场景更可能受益于分散放置。

## 相关研究的最小结论

- `Sandwich`：CPU LLM 推理不能只看 `NUMA`，还要看更细的共享缓存拓扑；`decode` 阶段常能通过拓扑感知的核心选择获益。
- `ARCAS`：本地 chiplet 访问可到约 `25ns`，同 socket 不同 chiplet 约 `80-90ns`，跨 socket 更高；系统根据远端访问率在“集中”和“分散”之间动态切换，本质是在“更低延迟”和“更大聚合缓存”之间切换。
