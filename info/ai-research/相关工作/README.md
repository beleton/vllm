# 相关工作检索入口

## 目录角色
- `../../../wiki/资料总览/相关工作检索清单.md`：正式结果文档，也是跨任务的主交接入口。
- `../../../wiki/资料总览/相关工作论文筛选与研究方向建议.md`：基于正式清单和 `info/进展.md` 做的二次筛选、总结与研究方向建议。
- `2026-03-31_chiplet_llm_相关工作候选池.md`：检索过程中的候选资料池，允许重复发现后再统一去重。
- `sources/`：保存原始联网检索结果、网页摘录或搜索输出；正式结论不要只留在 `sources/`，要回写到上面两份文档。

## 任务执行口径
每次启动一个新对话执行相关工作检索任务时，开始前统一阅读：
- `info/进展.md`
- `tasks.json`
- `process.txt`
- `info/README.md`
- 当前文件
- `wiki/资料总览/相关工作检索清单.md`
- `wiki/资料总览/相关工作论文筛选与研究方向建议.md`
- `2026-03-31_chiplet_llm_相关工作候选池.md`

## 交接规则
- 主交接写在 `wiki/资料总览/相关工作检索清单.md` 的“任务交接/下一步”部分。
- 候选资料、暂未去重条目、待核实来源写入候选池文档。
- 只有执行层面的临时事项才写入 `process.txt`，例如网页无法访问、搜索脚本报错、API 限制、某个原始结果文件损坏。不要把系统化结论写进 `process.txt`。

## 资料记录要求
- 用中文，简洁。
- 结论必须绑定资料来源；如果只是根据资料做推断，要明确写“推断，不是原文直接结论”。
- 优先记录绝对日期或年份。
- 对每条资料尽量补齐：标题、作者/机构、年份或绝对日期、类型、硬件/平台、研究对象或工作负载、核心优化点、与当前课题的关联点、相关性评级、资料链接。

## 本轮检索目标
- 优先收集与 LLM 推理、attention、KV 共享工作集、绑核、NUMA、数据放置、拓扑感知调度相关的资料。
- 可纳入相近平台：chiplet CPU、NUMA-like CPU、分片 LLC、多 die GPU、GPU NUMA、MCM/XCD/GCD 等。
- 最终目标不是只留搜索记录，而是沉淀出可直接阅读的正式资料清单。
