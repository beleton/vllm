## 1. 当前证据基线

- `Prefill/Decode` 分相结果已经证明：在 `B16/I1024/O1` 与 `B16/I1/O1024` 这组负载下，`decode` 的 `L3 Miss %` 和 `Ave L3 Miss Latency` 明显高于 `prefill`。证据目录分别是：
  - `test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I1024_O1/metric2_l3_dc_l2_memory/AMDuProfPcm-Multi_Mar-23-2026_20-27-32`
  - `test_results/PD_Test/Qwen3-30B-A3B/PCm_res/decode_B16_I1_O1024/metric2_l3_dc_l2_memory/AMDuProfPcm-Multi_Mar-23-2026_20-48-58`
- `decode` 长度 sweep 现有批次已经显示一个稳定现象：`O64/O128/O256/O512/O1024` 下，`L3 Miss %` 基本稳定在 `96.34%~96.74%`，`Ave L3 Miss Latency` 基本稳定在 `326~328 ns`，`Remote DRAM Reads %` 仍约为 `0.03%`。对应目录在 `test_results/PD_Test/Qwen3-30B-A3B/PCm_res/decode_B16_I1_O*/...`。
- `prefill` 长度 sweep 则不是平的：`I128/I512/I1024` 的 `L3 Miss %` 为 `8.82/14.55/49.43`，`same-node another CCX %` 为 `25.42/11.65/2.91`，说明 prefill 更像是随着输入长度跨过某个工作集阈值后，访问来源和 miss 形态发生切换。对应目录在 `test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I128_O1/...21-06-25`、`.../prefill_B16_I512_O1/...20-59-21`、`.../prefill_B16_I1024_O1/...20-27-32`。
- `prefill_B16_I256_O1` 这批数据当前不适合直接并入趋势分析：`2026-03-26 14:26:52` 的 `report-cumulative.csv` 给出 `Total Mem Bw=6.71 GB/s`，与相邻 `I128=93.99 GB/s`、`I512=142.69 GB/s` 明显不连续。证据目录：`test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I256_O1/metric2_l3_dc_l2_memory/AMDuProfPcm-Multi_Mar-26-2026_14-26-52`。
- 源码侧已经有明确静态证据说明：prefill attention 中，同一 `kv_head` 会被拆成多个线程任务，且不同线程可能读取高度重叠的 KV 前缀；这给“按共享 K/V 工作集做局部性优化”提供了理由。证据位置：`csrc/cpu/cpu_attn_impl.hpp:436-589`、`csrc/cpu/cpu_attn_impl.hpp:1424-1459`、`csrc/cpu/cpu_attn_impl.hpp:1527-1538`、`csrc/cpu/cpu_attn_impl.hpp:1631-1727`。
- 但当前还没有函数级证据证明：`decode` 的高 `L3 miss` 主要来自 attention，而不是 `MoE/MLP`、`TP all_reduce` 或其他路径。`info/实验记录/2026-03-25_当前对话进度交接.md` 已经明确把这一点列为当前最大证据空白。
- NPS/TP 的系统级证据已经表明，不同拓扑切分会显著影响吞吐和远端访存，但当前最稳的事实结论只到 `NPS2_TP4` 是现有 Qwen3-30B-A3B 批次中的甜点区；还不能直接推导出“attention 局部性优化一定能提升端到端”。证据：`test_results/NPS_Test/Qwen3-30B-A3B_analysis/docs/Qwen3-30B-A3B_analysis_report.md`。

## 2. 下一阶段总目标

下一阶段不应直接进入“改 attention 调度策略”或“大规模扫 NPS/TP”。

更合理的主线是：

1. 先补齐 `Prefill/Decode` 的函数级归因，确认高 `L3 miss` 主要落在哪条调用链。
2. 若 attention 确实是主贡献者，再建立更贴近真实 `block_table/slot_mapping/query_start_loc/seq_lens` 的 attention 试验台，验证局部性假设。
3. 只有在前两步都成立时，才进入 `NPS`、`TP`、线程绑核和 NUMA 内存策略的系统级优化实验。

换句话说，下一阶段的核心不是“先做优化”，而是“先把主矛盾证明清楚”。

## 3. 研究方向与优先级

### P0：补齐 `Prefill/Decode` 的函数级归因

这是最高优先级，原因有两个：

- 现有 `PCM` 只能证明 phase 级现象，不能回答“谁制造了 miss”。
- 如果 miss 主体不在 attention，后续把时间投入到 attention 局部性会偏题。

具体实验：

1. 以现有两组基线负载为主：
   - `decode_B16_I1_O1024`
   - `prefill_B16_I1024_O1`
2. 先继续用 `AMDuProfPcm` 锁定稳定时间窗，再按 `info/experiment_ops/Qwen3-30B-A3B_attention归因与局部性实验总步骤.md` 跑：
   - `hotspots`
   - `IBS OP + L3 miss filter`
3. 对每组 workload 输出两类结果：
   - CPU 时间 Top 函数/调用链
   - `L3 miss` 样本 Top 函数/调用链

进入下一阶段的判据：

- 若 `cpu_attn.cpp / cpu_attn_impl.hpp / cpu_attention_with_kv_cache` 路径同时占据主要 CPU 时间或主要 `L3 miss` 样本，则继续把 attention 作为主方向。
- 若主要样本落在 `cpu_fused_moe`、`linear`、`tensor_model_parallel_all_reduce` 或通信等待路径，则把研究重心切到 `MoE/TP`，不再默认 attention 是第一方向。

### P1：清洗并补齐 phase 内部长度曲线

这一阶段的目标是把“phase 级平均现象”拆成更细的长度区间行为。

具体实验：

1. 先复验异常批次 `prefill_B16_I256_O1`，不让异常点污染后续判断。
2. 在 prefill 侧补更细的输入长度点，优先建议：
   - `I256` 复验
   - `I768`
   - `I1536` 或 `I2048`
3. decode 侧暂时不急着继续扩点，因为现有 `O64/O128/O256/O512/O1024` 已经表明 `L3 Miss %` 长时间维持在约 `96%`；当前更缺的是函数归因，不是更多 decode 点。

这一阶段要回答的问题：

- prefill 的转折点到底出现在什么长度区间。
- 为什么 prefill 随输入变长时，`same-node another CCX %` 明显下降，但 `Remote DRAM Reads %` 仍很低。
- decode 为什么在 `Remote DRAM Reads %` 几乎不变的情况下，仍长期维持极高 `L3 Miss %` 和高 `Ave L3 Miss Latency`。

### P2：建立更贴近真实运行时的 attention 局部性试验台

当前 `benchmark_cpu_attn.py` 只能做“kernel 是否对 shape 敏感”的辅助对照，不能直接解释端到端 `Prefill/Decode` 差异。原因已经在 `info/实验记录/2026-03-25_当前对话进度交接.md` 写明：它的 `block_table` 是随机生成的，`slot_mapping` 也是连续构造的。

因此，下一步更值得做的不是继续只跑随机微基准，而是做一个“trace/replay 型”试验台：

1. 从真实 `strict-batch` 运行中导出或重建：
   - `block_table`
   - `slot_mapping`
   - `query_start_loc`
   - `seq_lens`
   - 必要时补 `scheduler_metadata` 统计量
2. 用这些真实 metadata 驱动隔离的 CPU attention 实验。
3. 在这个试验台上再验证：
   - `kv_split on/off`
   - 同一 `kv_head` 任务是否集中到固定线程簇
   - 线程簇是否放在同一 `CCX` / 同一 NUMA node 更有利

这一阶段的目标不是立刻做 patch，而是先获得“真实 metadata 下 attention 是否真的对局部性敏感”的直接证据。

### P3：系统级拓扑实验，只在 P0/P2 成立后推进

如果 P0 证明 attention 是主 miss 来源，P2 又证明 attention 对局部性敏感，那么下一步才值得做系统级矩阵：

1. 固定 workload：
   - `decode_B16_I1_O1024`
   - `prefill_B16_I1024_O1`
   - 外加一个处在 prefill 转折区间的新长度点
2. 固定一个基准拓扑做对照，优先用已有表现最稳定的 `NPS2_TP4`。
3. 在此基础上拆开两个维度：
   - rank 级拓扑：`NPS/TP`
   - rank 内线程布局：`auto bind`、同 `CCX` 集中、同 socket 跨 `CCX` 分散、跨 node 分散
4. 指标仍绑定：
   - `CPI`
   - `Total Mem Bw`
   - `Ave L3 Miss Latency`
   - `L3 Miss Latency From another CCX in same node (%)`
   - `Remote DRAM Reads %`

这一步要避免一次把 `NPS`、`TP`、线程绑核和 NUMA 策略全混在一起扫，否则很难知道收益来自哪一层。

## 4. 推荐执行顺序

建议按下面顺序推进，避免跑偏：

1. `P0`：`decode_B16_I1_O1024` 的 `hotspots`
2. `P0`：`decode_B16_I1_O1024` 的 `IBS L3-miss`
3. `P0`：`prefill_B16_I1024_O1` 的 `hotspots`
4. `P0`：`prefill_B16_I1024_O1` 的 `IBS L3-miss`
5. `P1`：复验 `prefill_B16_I256_O1`
6. `P1`：补 `prefill` 转折区间长度点
7. 只有当 `P0` 支持 attention 主导时，才进入 `P2`
8. 只有当 `P2` 也支持局部性敏感时，才进入 `P3`

## 5. 现阶段不建议立即做的事

- 不建议现在就写 Chiplet-aware attention 调度 patch。当前缺的是主路径归因证据，不是优化想法。
- 不建议在没有复验 `prefill_B16_I256_O1` 之前，把它并入 prefill 长度趋势图。
- 不建议继续把随机 `benchmark_cpu_attn.py` 结果当作端到端 `Prefill/Decode` 差异的直接证据。
- 不建议现在就全面重扫 `NPS1/NPS2/NPS4 × TP × bind` 大矩阵；在没有函数级归因之前，这类实验成本高、解释难。

## 6. 预期产出

如果按上面的顺序推进，下一轮最有价值的产出应当是：

1. 一份带函数名和调用链的 `Prefill/Decode` 归因结论，而不再只是 phase 级均值。
2. 一张干净的 prefill 长度转折曲线，明确工作集切换点。
3. 一个能复用真实 metadata 的 attention 局部性试验台，作为后续 Chiplet-aware 优化前的验证平台。

这三项完成后，再讨论“该不该改 attention 调度策略”会更稳。
