## 研究课题
相比单片架构的CPU，Chiplet架构将CPU分为了多个CCD，L3 Cache在物理上分散在不同的CCD内部，核心访问本CCD/CCX的L3最快，访问同CPU内其他CCD/CCX的L3更慢，呈现类似NUMA的本地和远端的现象。当前课题是研究如何在Chiplet架构的CPU上，针对其硬件特性，优化LLM推理服务。

## 本机硬件
本机为 `2 x AMD EPYC 9745 128-Core Processor`。`lscpu` 显示共有 `512 MiB L3`、`16 instances`；结合双路配置，可对应为每个物理 CPU 有 `8` 个 `32 MiB` 的本地 L3 slice，每个 slice 对应 `16` 个物理核心。

## 当前进展

### 启发论文
1. `ARCAS: Adaptive Runtime System for Chiplet-Aware Scheduling`
   - 论文的核心启发是：Chiplet CPU 的分片 L3 带来“局部性 vs 聚合缓存容量”的权衡。任务集中在更少 chiplet 上时，本地缓存访问延迟更低；任务分散到更多 chiplet 上时，可用的聚合缓存更大，但访问延迟也更高。
   - 这篇论文的评测对象是图处理、统计分析、OLAP/OLTP 等内存密集型并行程序，不是 LLM 推理。因此它能提供的是调度思路，而不是可直接套用到 vLLM 的结论。
   - 证据：`info/papers/ARCAS.pdf` 第 1-2 页。
2. `OPTIMIZING ATTENTION ON GPUS BY EXPLOITING GPU ARCHITECTURAL NUMA EFFECTS`
   - 论文把“共享同一组 K/V 的 workgroup 集合”定义为 `ACC (Attention Compute Cluster)`；在 MHA 中，一个 ACC 对应同一 attention head 的 workgroup 集合，在 GQA 中则对应一组共享 K/V 的 grouped heads。
   - 论文的核心优化不是泛泛地“把 workgroup 放近一点”，而是尽量让同一 ACC 落在同一 `XCD`，以提高 L2 复用并减少重复 HBM 读取。
   - 这篇论文直接研究的是 GPU attention，但“按共享 K/V 工作集做拓扑感知放置”的思路，可作为 CPU prefill 局部性优化的参考。
   - 证据：`info/papers/GPU_Attention_NUMA_Optimization.pdf` 第 1 页和第 5 页。

### 实验观察
1. CPU prefill 阶段存在“同一 `kv_head` 下多个线程重复读取重叠 KV 前缀”的局部性模式，这为后续做 Chiplet/CCD 感知的局部性优化提供了依据。
   - `cpu_attn_get_scheduler_metadata` 先按 `kv_len_per_thread` 和 `remaining_kv_len` 做负载均衡式 workitem 切分，而不是按共享 K/V 工作集直接聚类。证据：`csrc/cpu/cpu_attn_impl.hpp:436-589`。
   - 运行时的 attention task 会展开成 `actual_kv_head_num * effective_thread_num`，同一个 `kv_head` 会对应多个线程桶。证据：`csrc/cpu/cpu_attn_impl.hpp:1424-1459`。
   - 每个 task 都会按 `curr_kv_head_idx` 从全局 `key_cache/value_cache` 取数；在 causal prefill 下，后续 `q_tile` 会看到更长的 KV 前缀，因此不同线程上可能出现高度重叠的 KV 读取。证据：`csrc/cpu/cpu_attn_impl.hpp:1527-1538`、`csrc/cpu/cpu_attn_impl.hpp:1556-1561`、`csrc/cpu/cpu_attn_impl.hpp:1631-1727`。
   - 论文 2 中“把共享 K/V 工作集尽量放在同一局部域”的思路，可作为这里的参考。
2. 当前 `Prefill/Decode` 分相实验已经支持一个明确观察：在 `B16/I1024/O1` 与 `B16/I1/O1024` 这组配置下，decode 的 L3 压力显著高于 prefill。
   - `prefill_B16_I1024_O1`：`L3 Miss %=49.43`，`Ave L3 Miss Latency=180.12 ns`，`L3 Miss Latency From another CCX in same node %=2.91`，`Remote DRAM Reads %=0.03`。证据目录：`test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I1024_O1/metric2_l3_dc_l2_memory/AMDuProfPcm-Multi_Mar-23-2026_20-27-32`。
   - `decode_B16_I1_O1024`：`L3 Miss %=96.51`，`Ave L3 Miss Latency=326.57 ns`，`L3 Miss Latency From another CCX in same node %=1.51`，`Remote DRAM Reads %=0.03`。证据目录：`test_results/PD_Test/Qwen3-30B-A3B/PCm_res/decode_B16_I1_O1024/metric2_l3_dc_l2_memory/AMDuProfPcm-Multi_Mar-23-2026_20-48-58`。
   - 这批数据表明：decode 比 prefill 更容易出现高 `L3 Miss` 和高 `Ave L3 Miss Latency`，同时 `Remote DRAM Reads %` 在这两组实验里都维持在 `0.03%`。
3. Prefill 内部不同输入长度的访存特征差异较大。
   - `prefill_B16_I128_O1`：`L3 Miss %=8.82`，`Ave L3 Miss Latency=287.01 ns`，`same-node another CCX %=25.42`。
   - `prefill_B16_I512_O1`：`L3 Miss %=14.55`，`Ave L3 Miss Latency=177.99 ns`，`same-node another CCX %=11.65`。
   - `prefill_B16_I1024_O1`：`L3 Miss %=49.43`，`Ave L3 Miss Latency=180.12 ns`，`same-node another CCX %=2.91`。
   - 证据目录分别为 `test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I128_O1/...21-06-25`、`test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I512_O1/...20-59-21`、`test_results/PD_Test/Qwen3-30B-A3B/PCm_res/prefill_B16_I1024_O1/...20-27-32`。
4. 这部分结论当前主要绑定 `test_results/PD_Test/Qwen3-30B-A3B/PCm_res` 下的 PCM 累计结果，对应时间戳包括 `2026-03-23 20:27:32`、`2026-03-23 20:48:59`、`2026-03-23 20:59:21`、`2026-03-23 21:06:25`。
5. `P2` 的 `attention-only` `NPS1_TP2` 首轮结果支持把“按共享 K/V 工作集做拓扑感知放置”当作 `prefill` 的候选优化方向，但当前证据还不足以证明它已经可稳定实现、也不足以证明它能跨 `NPS/TP` 泛化。
   - 在 `prefill-like/global-fixed/batch_16` 下，`q=128/256/512` 时 `same-node another CCX %=99.13/94.00/61.15`，而 `Ave L3 Miss Latency=432.37/199.23/155.80 ns`；说明短到中等长度的 `prefill` 里，跨 CCX 路径占比很高，存在局部性优化靶点。证据：`test_results/P2_AttnOnly/Qwen3-30B-A3B/NPS1_TP2/summary.md`。
   - 但在同一批结果里，`q=1024/2048` 时 `local memory / I/O %=68.80/77.32`，而 `same-node another CCX %=30.70/21.95`；说明长 `prefill` 的主导来源已经更偏本地内存，这时仅靠“把共享 K/V 收到同一 CCX”未必还能打中主要瓶颈。证据：`test_results/P2_AttnOnly/Qwen3-30B-A3B/NPS1_TP2/summary.md`。
   - 当前覆盖范围只有 `NPS1_TP2 + global-fixed + batch=16`，`prefill-like` 只跑了 `q=kv=128/256/512/1024/2048`，`decode-like` 只跑了 `q=1, kv=256/512/1024/2048`；还没有 `NPS2_TP4 / NPS4_TP8`，也没有 `per-rank-fixed` 对照，因此只能写成阶段性观察。证据：`test_results/P2_AttnOnly/Qwen3-30B-A3B/NPS1_TP2/summary.md`、`info/experiment_ops/Qwen3-30B-A3B_attention-only_TP实验步骤.md` 第 3-4 节。

### 接下来目标
1. 根据实验观察1，研究如何优化prefill任务的attention
2. 根据实验观察2与实验观察5，继续刻画 `Prefill/Decode` 的 `L3` 访存特征和 `L3 Miss` 来源，优先补齐下面几类实验，再判断是否值得做拓扑感知调度优化。
   - 先补 `NPS2_TP4 / NPS4_TP8` 的 `global-fixed`，否则无法判断“任务分散到更多 chiplet”后，当前 `same-node another CCX` / `local memory` 趋势会变强还是变弱。证据：`info/experiment_ops/Qwen3-30B-A3B_attention-only_TP实验步骤.md` 第 3.9 节和第 4.3 节。
   - 再补 `per-rank-fixed`，把“拓扑局部性变化”与“每个 rank 工作量变小”分开。证据：`info/experiment_ops/Qwen3-30B-A3B_attention-only_TP实验步骤.md` 第 1 节对 `global-fixed/per-rank-fixed` 的定义，以及第 4.4 节。
   - 在长度上，当前 `prefill` 的来源切换主要发生在 `q=512 -> 1024` 区间，`decode` 的来源切换主要发生在 `kv=1024 -> 2048` 区间；现有点位只能看到粗趋势，还不足以定位转折点。证据：`test_results/P2_AttnOnly/Qwen3-30B-A3B/NPS1_TP2/summary.md`。
   - 当前只覆盖 `batch=16`。这足够做 kernel 级首轮定位，但不足以说明 batch 敏感性；若后续目标是给服务侧写结论，至少还要补一个更低 batch 和一个更高 batch。这里是基于覆盖范围缺口做的推断，不是现有数据已经证明的结论。
