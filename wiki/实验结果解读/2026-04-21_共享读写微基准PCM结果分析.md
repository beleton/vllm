# 2026-04-21 共享读写微基准 PCM 结果分析

## 范围
- 数据目录：`test_results/microbench/`
- case：
  - `read_shared_cache/same_ccd_2t_8m`
  - `read_shared_cache/cross_ccd_2t_8m`
  - `write_shared_cache/same_ccd_2t_8m`
  - `write_shared_cache/cross_ccd_2t_8m`
- 当前目录下原始结果文件为 `report.json`，没有 `report-cumulative.csv`
- 本文统一使用各 `report.json` 中 `group=system` 的聚合指标
- 写共享微基准的访问语义来自 `tools/microbench/write_shared_cache.c`
  - 多线程反复覆盖同一批共享 cache line 的第一个 `_Atomic uint64_t`
  - 每次写使用 `memory_order_relaxed`
- 只读微基准的访问语义来自 `tools/microbench/read_shared_cache.c`
  - 多线程反复读取同一批共享 cache line 的第一个 `uint64_t`
- 这两组微基准只用于拆分“共享只读”和“共享写回”两类 cache 行为，不直接等价于 attention 的真实执行路径

## 核心结论
- 写共享跨 `CCD` 明显更差
  - `IPC (Sys + User)` 从 `0.22` 降到 `0.16`，下降 `27.27%`
  - `Demand DC Fills From another CCX in same node (pti)` 从 `0.15` 升到 `57.22`，放大约 `381x`
  - `L3 Miss %` 从 `21.58%` 升到 `94.07%`
- 写共享跨 `CCD` 的主代价不在 `DRAM`
  - `Demand DC Fills From Local Memory or I/O (pti)` 仅 `0.04 -> 0.10`
  - `Demand DC Fills From Remote memory or I/O (pti)` 仅 `0.03 -> 0.01`
  - 主要变化来自 `another CCX in same node`
- 只读共享没有出现同等级别的跨 `CCD` 恶化
  - `IPC` 仅 `0.17 -> 0.15`
  - `Demand DC Fills From another CCX in same node (pti)` 仅 `0.18 -> 0.06`
  - `L3 Miss %` 仅 `0.74% -> 0.55%`
- 这批结果支持的结论是：跨 `CCD` 共享写会引入显著的同节点其他 `CCX` 路径代价；只读共享没有复现同等级别现象

## 1. 写共享：same CCD vs cross CCD

| 指标 | same CCD | cross CCD | 变化 |
| --- | ---: | ---: | ---: |
| `Utilization (%)` | 7.97 | 9.17 | +1.20 pp |
| `Eff Freq (MHz)` | 2432.29 | 2432.11 | 基本一致 |
| `IPC (Sys + User)` | 0.22 | 0.16 | `-27.27%` |
| `Demand DC Fills From Local L2 (pti)` | 30.43 | 3.86 | `-87.31%` |
| `Demand DC Fills From Local L3 or different L2 in same CCX (pti)` | 33.44 | 1.31 | `-96.08%` |
| `Demand DC Fills From another CCX in same node (pti)` | 0.15 | 57.22 | `381.47x` |
| `Demand DC Fills From Local Memory or I/O (pti)` | 0.04 | 0.10 | 都很小 |
| `Demand DC Fills From Remote memory or I/O (pti)` | 0.03 | 0.01 | 都很小 |
| `L3 Access (pti)` | 78.75 | 69.96 | `-11.16%` |
| `L3 Miss (pti)` | 17.34 | 65.97 | `3.80x` |
| `L3 Miss %` | 21.58% | 94.07% | `+72.49 pp` |
| `Ave L3 Miss Latency (ns)` | 263.14 | 128.75 | `-51.07%` |

直接观察：
- 跨 `CCD` 写共享时，补线主路径从本地 `L2/L3` 转成 `another CCX in same node`
- `IPC` 下降与 `L3 miss` 比例升高同时出现
- 内存相关 fill 仍接近 `0`

这组数据不支持把跨 `CCD` 写共享的主因写成 `DRAM` 带宽或远端内存访问。

## 2. 只读共享：same CCD vs cross CCD

| 指标 | same CCD | cross CCD | 变化 |
| --- | ---: | ---: | ---: |
| `Utilization (%)` | 8.00 | 9.50 | +1.50 pp |
| `Eff Freq (MHz)` | 2432.02 | 2432.04 | 基本一致 |
| `IPC (Sys + User)` | 0.17 | 0.15 | `-11.76%` |
| `Demand DC Fills From Local L2 (pti)` | 103.30 | 111.92 | `+8.34%` |
| `Demand DC Fills From Local L3 or different L2 in same CCX (pti)` | 4.38 | 3.93 | `-10.27%` |
| `Demand DC Fills From another CCX in same node (pti)` | 0.18 | 0.06 | `-66.67%` |
| `Demand DC Fills From Local Memory or I/O (pti)` | 0.05 | 0.01 | 都很小 |
| `Demand DC Fills From Remote memory or I/O (pti)` | 0.03 | 0.01 | 都很小 |
| `L3 Access (pti)` | 117.18 | 118.39 | `+1.03%` |
| `L3 Miss (pti)` | 0.85 | 0.64 | `-24.71%` |
| `L3 Miss %` | 0.74% | 0.55% | `-0.19 pp` |
| `Ave L3 Miss Latency (ns)` | 261.52 | 255.47 | `-2.31%` |

直接观察：
- 只读共享两种放置下，`L3 miss` 都很低
- `another CCX in same node` 没有像写共享那样显著升高
- 只读共享没有出现“跨 `CCD` 后 remote fill 大量上升”的现象

## 3. 读写对照下最值得汇报的点

### 3.1 写共享和只读共享的分界很明显
- 写共享跨 `CCD`：
  - `IPC` 更低
  - `L3 Miss %` 极高
  - `another CCX in same node` fill 极高
- 只读共享跨 `CCD`：
  - `IPC` 只有小幅变化
  - `L3 Miss %` 仍接近 `0`
  - `another CCX in same node` fill 没有放大

### 3.2 `Ave L3 Miss Latency (ns)` 不能单独当作性能结论
- 写共享里，跨 `CCD` 的 `Ave L3 Miss Latency (ns)` 从 `263.14` 降到 `128.75`
- 但同一组数据里：
  - `IPC` 更低
  - `L3 Miss (pti)` 更高
  - `L3 Miss %` 更高
  - `another CCX in same node` fill 大幅升高
- 因此这批数据不能写成“平均 miss 延迟更低，所以跨 `CCD` 更快”；必须和 miss 数量、miss 比例、来源路径一起看

### 3.3 这批 microbench 对 attention 讨论的作用边界
- 写共享微基准证明的是：跨 `CCD` 共享写会引入很强的同节点其他 `CCX` 路径代价
- 只读微基准证明的是：共享只读访问没有复现同等级别的跨 `CCD` 恶化
- attention 的 `KV` 主体是只读访问，因此不能把写共享微基准里的跨 `CCD` 代价直接外推到 attention 的 `KV` 路径

## 4. 汇报可直接使用的结论
- `write_shared_cache` 的 `same CCD -> cross CCD` 对照里，`IPC` 从 `0.22` 降到 `0.16`，`Demand DC Fills From another CCX in same node (pti)` 从 `0.15` 升到 `57.22`，`L3 Miss %` 从 `21.58%` 升到 `94.07%`
- 这说明跨 `CCD` 共享写的主代价在同节点其他 `CCX` 路径，不在 `DRAM`
- `read_shared_cache` 的同口径对照没有出现相同现象；只读共享下 `L3 Miss %` 始终低于 `1%`
- 因此，跨 `CCD` 强负效应主要出现在共享写，不在共享只读；不能把写共享测到的代价直接当作 attention 只读 `KV` 的代价

## 5. 边界
- 当前只覆盖 `2 threads / 8 MiB / same CCD vs cross CCD`
- 当前数据目录只有 `report.json`，本文没有使用 `report-cumulative.csv`
- 写共享程序只覆盖每条 cache line 的第一个 `8B`
- 写共享程序使用 `_Atomic uint64_t` + `memory_order_relaxed`，测到的是这一路径下的共享写行为
- 本文不把微基准结果直接外推为 attention 真实执行时间，只把它当作读写共享 cache 行为的对照证据
