# 2026-05-06 Qwen3-30B-A3B CPU Attention L3局部性优化结论
## ACC思路
`balanced` 使用全局动态抢任务。单个 `kv_head` 的 workitem 可以被多个 `CCD/L3` 上的线程领取，同一个 `CCD` 也可以同时承接多个 `kv_head`。该路径容易形成同一只读 `K/V` 工作集在多个本地 `L3` 中的副本，也会增加一个本地 `L3` 同时容纳多个 `kv_head` 前缀的容量压力。

`acc-local-l3` 按 `(numa_node, socket_id, l3_cache_id)` 划分线程 `subgroup`，再把 `kv_head` 分配给指定 `subgroup`。在 `group_span=1`、每个 rank 有 `8` 个本地 `kv_head`、每个 socket 有 `8` 个本地 `L3` subgroup 的口径下，可按“每个本地 `kv_head` 固定到一个本地 `L3/CCD` 域”理解。该策略主要改变任务领取范围，不改变 attention 数学 kernel。

`q256` 的日志显示：`balanced` 下单个 `kv_head` 最多横跨 `5` 个 `CCD`，单个 `CCD` 最多同时计算 `7` 个 `kv_head`；`acc-local-l3` 下每个 `kv_head` 只落在 `1` 个 `CCD`，每个 `CCD` 只计算 `1` 个 `kv_head`。策略已经生效。

## CAT容量限制
CAT 实验使用 `resctrl` 控制每个本地 `L3/CCD` 的可用 cache mask。`ffff` 是全开（不限制），`0001` 是将每个本地 `L3` 的可用容量压缩到约 `1/16`（极端限制）。实验在 `span1 occupancy` 口径下采集，同时记录 `resctrl` 报告的 `L3 occupancy` 和 PCM 报告的 `llc_occupancy`。

下表中的对比基准统一为 `ffff`，即 `0001` 相对 `ffff` 的变化。若本地 `L3` 容量和 `K/V` 副本冗余是当前 attention 的主性能杠杆，`0001` 应在长序列上造成显著退化。

runtime 角度：
- `0001` 对 `q8192+` 的影响只有 `0.03%~2.11%`，短序列 `q1024/q4096` 相对更敏感（`+1.45%~+8.80%`），但短序列的 runtime 绝对值很小且不在主优化区间。长序列对本地 `L3` 容量限制不敏感。
- 否定了”当前 attention 的主要瓶颈是本地 `L3` 容量不足或 `K/V` 副本冗余”的判断。

resctrl L3 occupancy 角度：
- `ffff` 下，随着序列增长总 L3 occupancy 均值和峰值均上升：`q1024` 均值约 `72 MB` 峰值约 `249 MB`，`q65536` 均值约 `252~370 MB` 峰值约 `384~497 MB`。单个 CCD 有 `32 MB` 的本地 L3 容量，16 个 CCD 总理论容量约 `512 MB`。长序列的峰值已接近总容量上限。
- `0001` 将可用容量压缩到 `ffff` 的约 `1/16`，总 L3 occupancy 被严格压缩到均值约 `6~26 MB`、峰值约 `25~33 MB`，与 CAT mask 的预期一致。该约束生效，但 runtime 几乎不受影响。
- `acc-local-l3` 在 `ffff` 下的总 occupancy 均值略低于 `balanced`（如 `q65536`：`251.8 MB` vs `370.0 MB`），说明任务收敛策略确实改变了 L3 驻留形态。但这种变化没有转化为 runtime 收益。

### 解释

`q8192+` 在 `0001` 下只退化 `0.03%~2.11%`，但 `ffff` 下的 occupancy 数据显示长序列已经形成大量稳定的 L3 驻留（`q65536` 均值 `240~370 MB`）。CAT 将驻留量压缩到约 `1/16`，runtime 几乎没变。这明确说明：

- 那些在 `ffff` 下驻留在 L3 中的数据（主要是 `K/V` tile 和中间结果）不在主要性能关键路径上。
- 数据以流式扫描、预取、短生命周期 cache line 为主。L3 容量被压缩后，这些 cache line 由本地 L2 和预取机制承接，没有显著增加关键路径等待。

attention 运行期间确实形成了大量 L3 驻留，但这些驻留数据不重要。本地 L3 副本冗余的优化，作用对象是这些不重要的驻留数据。

## 结论
1. cache 行为改善没有转成 runtime 收益。`q8192+` 的 `L3 Miss / task` 下降 `17.19%~53.06%`，L3 occupancy 均值降低 `23%~32%`（`q65536 acc-local-l3: 251.8 MB vs balanced: 370.0 MB`），runtime 仍退化 `8.21%~11.39%`。
2. 目标瓶颈不成立。跨 `CCD` demand fill 在 `q2048+` 仅约 `0.14%~0.81%`，主体 demand fill 来自本地 `L2`。
3. 容量假设不成立。极端 CAT `0001` 下 L3 occupancy 被压缩到 `ffff` 的约 `1/16`（均值从 `240~370 MB` 降到 `6~26 MB`），但 `q8192+` 只退化 `0.03%~2.11%`。说明 attention 对本地 `L3` 容量限制不敏感，那些在 `ffff` 下驻留的大量数据不在关键路径上。

## 下一步计划

寻找新的场景：
1. 应用对 L3 大小敏感，此时优化数据局部性、减少冗余，可以带来提升
2. 应用的各个线程/进程需要经常跨核心访问，此时可优化进程/线程的放置或计算过程，来减少跨 CCD 的访问
