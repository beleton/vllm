# 02 — L1 数据缓存与存储转发

## 2.1 L1D 的组织结构

### 基本参数（现代高性能核心典型值）

| 参数 | AMD Zen 5 | Intel Lion Cove |
|------|-----------|-----------------|
| 容量 | 48 KiB | 48 KiB |
| 相联度 | 12 路 | 12 路 |
| 行大小 | 64 B | 64 B |
| 访问延迟 | 4-5 cycle | 4-5 cycle (integer load-to-use) |
| 端口 | 2 load + 1 store/cycle | 3 load + 1 store/cycle (实际受 AGU 约束) |
| 写入策略 | Write-back, write-allocate | Write-back, write-allocate |
| 查找方式 | VIPT | VIPT |

### 物理布局

L1D 由三部分关键存储阵列组成，在一次 Load 访问中协同工作：

1. **Tag Array**：存储每路的物理 tag（物理地址高位），含 MESI 一致性状态位和替换元数据（LRU/RRIP）
2. **Data Array**：存储实际的 64 B 数据
3. **TLB**：虚拟→物理翻译（第 1 章已述）

### 访问路径（时序）

```
Cycle 0: AGU 计算有效地址 → 虚拟地址就绪
         │
         ├──→ bits[11:6] → Set Decoder → 选择 12 路中每路的 tag/way
         └──→ bits[47:12] → dTLB 查找 → 物理页号 (PPN)
                                           │
Cycle 1: Tag Array 读取（12 个 tag 同时读出）
                                           │
Cycle 2: PPN[高] 与 12 个 tag 比较 → 命中？→ Way 选择信号
                                           │
Cycle 3: Data Array 根据 way 选择读出 → 数据对齐与格式化
                                           │
Cycle 4: 数据写入物理寄存器文件，Load 完成
```

这是典型 4-cycle 的 L1D hit 路径。注意：cycle 0 的 AGU 地址生成和 set decode 是组合逻辑，不需要额外周期。关键路径在 Tag 比较和 Data 读出之间的串行关系——无法绕过，因为必须先确定 way 才能选择正确的数据输出。

### 缓存地址映射

给定物理地址 PA，在 L1D 中的位置由以下公式确定：

```
set_index  = (PA >> 6) & (num_sets - 1)    # bits[11:6] for 64 sets
tag        = PA >> 12                        # bits[47:12]
```

由于 VIPT 的关系，访问时使用的是虚拟地址的 bits[11:6]，而非物理地址的 bits[11:6]——两者相同（虚-实翻译不改变 page offset）。

### Bank 结构

为支持每周期多个并发的 Load，L1D 的数据阵列通常分为多个 bank。Bank 的选择由地址的低位决定（如 bits[2:0] 或 bits[3:0]）。同一周期内两个 Load 不能访问同一 bank——若地址落入同一 bank，其中一个被延迟。

这也是**对齐（alignment）影响性能**的微观原因之一：跨越 cache line 边界的非对齐访问需要两次独立的 bank 访问。

## 2.2 L1D 的替换策略

现代处理器普遍放弃真实 LRU（硬件成本高），改用近似方案：

### NRU（Not Recently Used）/ 伪 LRU

每路维护一个 1-bit 的 "recently used" 标志。替换时随机选择未使用的路。Zen 系常见此方案。

### RRIP（Re-Use Reference Interval Prediction）

Intel 自 Sandy Bridge 引入。每 cache line 维护一个 2-bit "re-reference prediction value"（RRPV），值越大表示重用可能性越低。访问命中时将 RRPV 清零，替换时选择 RRPV 最高的 line。若所有 line 的 RRPV 都等于最大值（如 3），则全部减一并重试。

RRIP 的优势在于对扫荡式访问（streaming，一次遍历不再用）更友好：streaming 数据获得较高 RRPV，优先被替换，不污染频繁访问的热数据。

### DRRIP（Dynamic RRIP）

Haswell 及以上支持动态 RRIP，硬件根据工作负载特征在 "偏向频繁访问" 和 "偏向扫荡" 两种模式间切换。通过在 L2/L3 的替换反馈信号上做训练。

## 2.3 写入策略

### Write-Back

- 写入仅更新 L1D（和可能的更低层级），不立即写入内存
- 修改过的 line 标记为 M（Modified）状态
- 被替换时（evict），若为脏（M/E 中独占且修改过），写回到下一级缓存（L2）

### Write-Allocate

- Store miss 时，先将对应 line 从下一级加载到 L1D（分配），再在 L1D 中执行写入
- 几乎所有现代 CPU 的 cacheable memory（WB 类型）使用 write-allocate

### 组合意义

Write-back + write-allocate 对大多数工作负载最优：延迟写入降低带宽压力，分配降低后续访问延迟。

## 2.4 Store Buffer 与存储转发

### 为什么需要 Store Buffer

Store 指令不能在 L1D 中立即写入，必须等到 Store 退休（retirement）后：

1. Store 是**不可逆的**操作——一旦写入缓存，无法在分支预测错误或异常时回滚
2. Store 地址可能依赖未就绪的源操作数
3. L1D 写入需先确认 tag 匹配和一致性权限，可能较慢

Store Buffer 在流水线的发射阶段介入：Store 指令的**地址和数据**完成后写入 Store Buffer，前端可以继续发射指令而不等待 L1D 实际写入。

### Store Buffer 结构

| 参数 | 典型值 |
|------|--------|
| 条目数 | 48-64（Zen 5），56-100+（Intel 大核心） |
| 每项内容 | 物理地址（48+ bit）+ 数据（64 B）+ 有效位 + 年龄（序列号）+ 字节使能掩码 |
| 写入时机 | Store 地址和数据就绪后立即写入 SB |
| 排出时机 | Store 退休后，按程序顺序写入 L1D（若 L1D 端口空闲） |

Store Buffer 条目在 Store 退休前一直处于**推测态**，退休后变为**非推测态**，等待写入 L1D。

### Store-to-Load Forwarding（存储→加载转发）

**核心机制**：当一个 Load 的地址与 Store Buffer 中某个未排出的 Store 地址**重叠**时，Load 的数据可以从 Store Buffer **直接转发**获取，无需等待 Store 写入 L1D 后再从 L1D 读取。

**转发条件（严格版本）**：

1. Store 地址与 Load 地址完全匹配（或 Store 完全包含 Load 的字节范围）
2. Store 比 Load 更老（程序顺序）
3. Store 的数据已就绪

**不允许转发的情况**：

- **部分重叠但不完全包含**：Load 地址跨越多个 Store 的覆盖范围，或 Store 与 Load 重叠但不覆盖全部字节。此情况下 Load 必须等待所有重叠 Store 写入 L1D 后才能执行
- **Store 地址尚未就绪**：Load 无法确定与未就绪 Store 是否重叠 → 必须保守等待，或做推测（2.5 节详述）
- **跨越 4 KiB 边界的 Load**：地址翻译可能不连续（虚拟连续 ≠ 物理连续），现代实现通常阻止此类转发并对齐检查

### 转发的微架构实现

Load Queue 同时监听 Store Buffer 的内容：

```
1. Load 获得虚拟地址
2. CAM（Content-Addressable Memory）在 Store Buffer 中查找匹配的物理地址
3. 若有匹配，比较程序年龄
4. 若 Store 更老且数据就绪 → 从 Store Buffer 数据字段转发
5. 若 Store 更老但数据未就绪 → Load 阻塞等待
6. 若所有匹配 Store 都比 Load 更年轻 → Load 忽略 Store Buffer，从 L1D 取数
7. 若无匹配 → Load 从 L1D 取数
```

步骤 2 要求 CAM 查找 Store Buffer 中的物理地址——即 Load 必须先获得物理地址（通过 TLB 或地址生成）。这引入了一个隐蔽的依赖：**Load 不仅依赖源寄存器（地址计算），还隐含依赖 TLB 翻译结果**，因为 Store Buffer 用物理地址做匹配。

### Store Buffer 大小对性能的影响

当 Store Buffer 满时，流水线前端必须停顿——即便指令窗口中有大量独立指令也无法发射新的 Store。这在 Store-intensive 的 kernel（如 memcpy、memset、加密算法）中可能形成瓶颈。Intel 和 AMD 在每代架构中持续扩大 Store Buffer。

## 2.5 内存排序模型（Memory Ordering）

### x86-TSO（Total Store Order）

x86-64 的内存模型是经典的 TSO 模型：

1. **Load 可以重排序**：Load 可以超越更早的 Load，也可以超越更早的 Store（到不同地址）
2. **Store 不能重排序**：Store 在程序顺序下不可超越其他 Store（实际上 Store 按顺序提交到 Store Buffer，按顺序排出到 L1D）
3. **同一地址的 Load/Store 不能重排序**
4. **Store→Load 转发保留程序顺序语义**（转发发生在 Store Buffer，是 X86 的强保证之一）

### ARM/POWER 的弱序模型

相较之下，ARM/POWER 的弱一致性模型允许更激进的重排——甚至传统 TSO 下不可重排的 Store-Store、同一地址 Load-Store，在弱序架构上都可以重排（除非显式插入 barrier/fence）。

### 实际约束下的 x86 TSO 实现

x86 微架构通过以下机制实现 TSO：

| 约束 | 实现机制 |
|------|---------|
| Store-Store 有序 | Store Buffer 按程序顺序（FIFO）写入 L1D |
| Load-Load 有序（同地址） | Load 地址 CAM 检测冲突，阻止重排 |
| Store-Load 有序（同地址） | Store-to-Load Forwarding 保证 Load 看到最近 Store |
| Store-Load 可重排（不同地址） | Load 可领先于未退休 Store 执行（推测性 Load） |
| Load-Store 不重排（同地址） | 若 Load 已执行而后续 Store 地址匹配 → 机器清除 |

### Memory Fence 指令

- **MFENCE**：序列化所有 Load 和 Store——在 MFENCE 之前的所有 Load/Store 必须在后续 Load/Store 之前全局可见
- **SFENCE**：序列化 Store——SFENCE 之前的所有 Store 在后续 Store 之前全局可见（但不约束 Load）
- **LFENCE**：序列化 Load——LFENCE 之后的 Load 不执行直到 LFENCE 之前的所有 Load 完成（也阻止推测执行）

MFENCE 的实际硬件开销：排空 Store Buffer + 等待所有 in-flight Load 完成 + 阻止后续指令发射。延迟通常在数十至上百周期。

## 2.6 Miss 处理：LFB 与 MSHR

### Line Fill Buffer（LFB）

LFB（Intel 术语，AMD 称 Miss Address Buffer / MAB）是 L1D miss 时的**未完成请求跟踪器**。每条 LFB 条目记录：

- 缺失的物理地址
- 请求类型（Load/Store/Prefetch）
- 目标寄存器/ROB 条目（Load 数据返回时投递目标）
- 请求状态（outstanding / partially filled / complete）

### MSHR（Miss Status Holding Register）

MSHR 和 LFB 在功能上类似。有些文献将 LFB 视为 MSHR 的一个子集。两者追踪未完成的 miss 请求。关键功能之一是 **miss 合并（Miss Coalescing）**：如果两个 Load 缺失同一 cache line，第二个 Load 不需要发起新的 miss 请求——直接复用已有 MSHR 条目，等待同一数据返回后一起满足。

### LFB 数量及其意义

| 处理器 | LFB/MSHR 数量 |
|--------|--------------|
| AMD Zen 5 | ~16-20 per core |
| Intel Golden Cove | ~16-20 per core |

LFB 数量决定了每个核心能承受的**并发 cache miss 深度**。当 LFB 满时，无法再发出新的 miss 请求——L1D 必须阻塞或拒绝后续 Load。这在链表遍历、指针追踪等 serialized-miss 模式下极易触发，即便内存系统有吞吐能力也被 LFB 瓶颈限制。

## 2.7 关键小节

- L1D 延迟是**所有访问延迟的最小值**——4-5 cycle 由物理约束（tag read → compare → data read）决定，工艺进步可略微改善但物理下限已近
- Store Buffer 使 Store 在流水线视角下 "零延迟"（不阻塞发射），代价是实现转发逻辑的复杂度
- Store-to-Load Forwarding 是 x86-TSO 强一致性的关键实现，同时避免了不必要的 L1D 往返
- LFB/MSHR 深度限制并发 miss 能力，是内存级并行的关键瓶颈
- 内存排序模型约束每次硬件的投机行为——x86 的 TSO 虽强，相比弱序在微架构优化上的自由度更低
