# Active Caching for Similarity Queries Based on Shared-Neighbor Information 解读

**一句话概述**：论文面向 top-k 相似查询提出 `CES`（Cache-Estimated Significance，缓存估计显著性）模型。它不是把查询结果完整命中后直接返回，而是利用缓存中已有对象的近邻列表和倒排近邻列表，基于“两个对象若经常出现在同一批对象的近邻列表中，则二者可能相似”的 shared-neighbor（共享邻居）信息，估计未缓存查询的 top-k 结果。实验显示，该方法在多个真实数据集上可显著提高应用级缓存命中率，并在命中时保持较高 recall。该论文不是 HNSW 论文，实验使用 SASH 生成近邻列表，也没有研究 CPU cache、NUMA 或 chiplet。

## 论文基本信息

- 作者：Michael E. Houle、Vincent Oria、Umar Qasim
- 会议：CIKM 2010

## 背景

### 相似查询

`Similarity query`（相似查询）指按相似度返回对象的查询。给定一个查询对象，系统返回数据库中最相似的若干对象。常见形式是 `k-NN`（k-nearest neighbor，k 近邻查询）：返回距离最近或相似度最高的 `k` 个对象。

这类查询广泛出现在推荐系统、多媒体数据库、搜索系统和信息检索中。与数据库中的精确匹配不同，相似查询通常无法只通过主键或布尔条件定位结果。系统需要计算查询对象与大量候选对象的相似度，或访问近似检索索引中的大量候选结构。因此，查询代价可能来自磁盘访问、索引遍历、距离计算和内存访问。

论文讨论的是应用级缓存，不是 CPU cache。这里的缓存保存的是查询结果列表、近邻列表和倒排列表，位于主存中，由系统显式管理。

### 论文实验中的底层检索算法

CES 本身不是近邻检索算法。它不负责从原始向量中搜索近邻，而是消费已经生成的近邻列表。论文实验中，近邻列表由 `SASH`（Spatial Approximation Sample Hierarchy，空间近似采样层次结构）计算。

SASH 是一种近似相似搜索结构。它将数据对象组织成多层随机采样层次：

```text
顶层：很少的采样对象
中间层：对象数逐层增加
底层：接近或包含全量对象
```

每一层中的对象来自下一层对象的随机子集，层级越高，对象越少。构建时，一个新对象会在已经建好的上层结构中寻找若干近似最近的父节点，并与这些父节点建立连接；父节点也维护指向下层子节点的连接。直观理解是：SASH 用少量上层采样点提供粗粒度导航，再逐层进入更大的样本集合。

SASH 查询一个对象 `q` 时，不扫描全体数据，而是从顶层开始逐层筛选候选：

```text
1. 从顶层候选集合开始。
2. 展开当前候选节点的下层子节点。
3. 计算 query q 与这些子节点的距离。
4. 保留距离 q 最近的一批节点。
5. 进入下一层，重复展开和筛选。
6. 到底层后，从访问过的候选对象中取距离最近的 k 个对象。
```

该过程返回的是近似 k-NN。近似性的来源是：每层只保留一部分候选，并不会检查所有可能路径。SASH 用候选保留数量控制速度与准确性的取舍。

论文实验没有把 SASH 作为贡献，也没有报告 SASH 的内部参数。它只说明使用 SASH 为每个数据集计算 100-NN 列表。后续 CES 缓存实验全部基于这些 100-NN 列表。

### 近邻列表的具体构造

对每个对象 `v`，底层检索结构按论文指定的距离函数计算或近似计算其他对象与 `v` 的距离，并按距离从小到大排序：

```text
rank(v, w) 越小  <=>  w 与 v 越相似
```

论文中的距离设置为：

- ALOI、CT、KDD：欧氏距离。对向量 `x` 和 `y`，距离按各维差值平方和再开方计算：

```text
d(x, y) = sqrt(sum_i (x_i - y_i)^2)
```

- RCV1：向量夹角距离。该距离按两个向量方向的夹角衡量相似性，通常由余弦值确定：

```text
cos(theta) = (x · y) / (||x|| ||y||)
```

夹角越小，两个文档向量越相似。论文没有给出 RCV1 夹角距离的实现细节；对排序而言，按夹角升序和按余弦相似度降序等价。

实验先为每个对象生成一个 100-NN 列表：

```text
Q(v, 100) = [v 的前 100 个近邻]
```

缓存实验使用的标准列表长度 `λ` 不一定是 100，而是从这个 100-NN 列表截取前 `λ` 个：

```text
Q(v, λ) = Q(v, 100) 的前 λ 个对象
```

例如 `λ = 30` 时，标准缓存列表只保存 `v` 的前 30 个近邻。若 `k = 30`，则 `Q(v, 30)` 同时可作为 top-30 查询结果和缓存标准列表。

由这些标准列表再构造倒排列表。若对象 `x` 出现在缓存对象 `u` 的 `Q(u, λ)` 中，就在 `x` 的倒排列表中记录 `u`：

```text
Q_C^-1(x, λ) = {u ∈ C : x ∈ Q(u, λ)}
```

因此，论文中的“近邻列表”有两级来源：

1. SASH 按距离函数为全体对象生成近似 100-NN 排名。
2. CES 从这些排名中截取前 `λ` 个，形成标准缓存和倒排缓存。

### 被动缓存与主动缓存

`Passive caching`（被动缓存）只在缓存中已有完整查询结果时命中。例如用户再次提交相同查询，系统直接返回已缓存的 top-k 列表。若缓存中没有这个查询对象的结果，系统回到数据库或索引执行完整查询。

被动缓存的收益依赖查询重复度。搜索引擎日志中可能存在高频重复查询，因此被动缓存有效。但相似查询未必有大量完全相同的查询对象。即使两个查询对象很接近，只要查询键不同，被动缓存仍会 miss。

`Active caching`（主动缓存）让缓存承担一部分查询处理功能。缓存中没有当前查询的完整结果时，系统尝试用已有缓存信息合成或估计结果。已有主动缓存工作主要面向布尔查询和语义缓存，例如用缓存中的集合包含关系回答新查询。论文指出，这类方法不能直接用于 top-k 相似查询，原因是 top-k 查询返回的是有序排名列表，不是满足条件的完整集合。

### 共享邻居信息

`Shared-neighbor`（共享邻居）思想的直观含义是：若两个对象经常与同一批对象相邻，则它们可能彼此相似。

例子：对象 `a` 和对象 `b` 没有直接计算过距离，但它们都出现在很多已缓存对象的前 30 个近邻中。这些已缓存对象相当于“见证者”。若见证者数量明显超过随机情况下的预期，则缓存支持 `a` 与 `b` 相似。

该思想不要求直接知道距离值。论文只使用近邻列表中的排名关系，即“某对象是否出现在另一个对象的前 `λ` 个结果中”。这使方法可以用于非度量相似度、概率模型和未知打分函数生成的结果列表。

### 与 HNSW 研究的关系

论文被放在 HNSW 资料目录下，原因是它讨论相似查询和近邻关系复用，但它的技术对象不是 HNSW 图索引。

它与当前 HNSW/chiplet 研究的关联点是：

- 相似 query 可能共享近邻集合；
- 可利用 query 之间或对象之间的邻域重叠估计复用价值；
- 缓存中保存的不是原始向量或图节点，而是查询结果列表和倒排关系。

它不能直接作为 HNSW 线程调度或 L3 局部性优化结果使用。论文没有测量图遍历访问路径、CPU cache miss、跨 CCD 访问、线程放置或硬件拓扑影响。

## 研究问题

论文研究的问题是：

```text
当 top-k 相似查询的完整结果没有被缓存时，能否只依赖缓存中已有的近邻列表，估计当前查询的 top-k 结果，并在可接受 recall 下减少访问原始数据库或索引的次数。
```

传统被动缓存只回答“缓存里有没有当前查询的结果”。论文改为回答：

```text
缓存里是否有足够证据支持某些对象应出现在当前查询的结果中。
```

该问题包含三个子问题：

1. **缓存命中扩展**：未显式缓存当前查询结果时，如何判断缓存仍可回答查询。
2. **候选对象排序**：如何用共享邻居信息给候选结果打分，并生成 top-k 列表。
3. **偏差校正**：缓存大小、缓存列表长度和倒排列表长度不同会影响共享邻居计数，如何避免简单计数偏向热门对象或长列表对象。

论文的核心假设是：缓存中保存的一批近邻列表可以作为数据空间的稀疏观测。如果一个查询对象和候选对象在这些观测中具有显著的共同见证者，则可用缓存估计二者相似。

## 问题模型

### 对象排名与近邻列表

设数据集为 `S`。对任意对象 `v`，存在一个按相关性或相似度排序的全局对象序列：

```text
(v1, v2, ..., v|S|)
```

`rank(v, w)` 表示对象 `w` 在 `v` 的相似度排序中的名次。排名越小，表示 `w` 对 `v` 越相关。

论文将 `Q(v, λ)` 定义为对象 `v` 的前 `λ` 个相关对象：

```text
Q(v, λ) = {v1, ..., vλ}
```

若执行 top-k 查询，`Q(v, k)` 就是查询 `v` 的理想结果列表。论文不要求知道实际距离或打分值，只要求已有对象可以产生这样的排名列表。

### 标准缓存

设 `C` 是被选入缓存的对象集合，`|C|` 是缓存对象数量。标准缓存保存每个缓存对象的前 `λ` 个近邻列表：

```text
C(C, λ) = {Q(v, λ) : v ∈ C}
```

直观理解：如果 `v` 被缓存，系统保存 `v` 的前 `λ` 个近邻。传统被动缓存只能在查询对象 `v ∈ C` 时直接返回 `Q(v, k)`。

### 倒排缓存

论文还构造 `inverted cache`（倒排缓存）。对任意对象 `u`，倒排缓存记录哪些缓存对象的近邻列表中出现过 `u`：

```text
Q_C^-1(u, λ) = {v ∈ C : u ∈ Q(v, λ)}
```

若 `u` 出现在很多缓存对象的近邻列表中，则 `Q_C^-1(u, λ)` 较大。这里的缓存对象可视为 `u` 与其他对象相似关系的见证者。

对于一个未显式缓存的查询对象 `v`，只要 `Q_C^-1(v, λ)` 非空，说明至少有缓存对象把 `v` 视为近邻。论文就尝试用这些见证者估计 `v` 的 top-k 结果。

## CES 模型设计

### 基本思想

CES 的输入不是距离值，而是缓存中的近邻列表和倒排近邻列表。对查询对象 `v` 和候选对象 `w`，论文比较二者的倒排缓存集合：

```text
Q_C^-1(v, λ)
Q_C^-1(w, λ)
```

若这两个集合有大量交集，表示很多缓存对象同时把 `v` 和 `w` 放进自己的前 `λ` 个近邻中。论文将这些共同出现解释为 `v` 与 `w` 相似的证据。

### 共享邻居度量

论文讨论三类基础度量。

**交集大小 `SimInt`**：

```text
SimInt_C,λ(v, w) = |Q_C^-1(v, λ) ∩ Q_C^-1(w, λ)|
```

该值表示 `v` 和 `w` 共享多少个缓存见证者。值越大，缓存越支持二者相似。缺点是容易偏向倒排列表很长的对象，即被很多缓存对象包含的热门对象。

**集合相关 `SimCorr`**：

`Set correlation`（集合相关）把集合看成 0/1 向量，再计算类似 Pearson 相关系数的值。它会考虑集合大小，避免只因某个对象倒排列表长就获得高分。

**余弦相似 `SimCos`**：

`Cosine similarity`（余弦相似）同样把集合看成 0/1 向量，用交集大小除以集合大小的几何平均。论文将它作为 `SimCorr` 的简化近似。实验中 `SimCos` 和 `SimCorr` 结果几乎相同，因此后续图中没有单独展示 `SimCos`。

### 显著性校正

直接使用共享邻居数会产生偏差。若某个候选对象出现在许多缓存列表中，它与任何查询对象都更容易有交集。若缓存列表长度 `λ` 更大，交集也会自然变大。论文用 `significance`（显著性）思想校正这些因素。

论文引入随机假设：假设每个缓存近邻列表是从数据集中随机选择的。真实共享邻居数若显著高于随机期望，说明它更可能反映真实相似关系。

在该假设下，论文推导 `SimInt` 和 `SimCorr` 的期望与方差，并将实际值转换为标准分数。标准分数衡量“实际共享程度比随机情况高出多少个标准差”。这种处理使不同缓存大小、列表长度和倒排列表大小下的分数更可比。

### 排名函数

论文最终评估六种排名函数：

- `SimRatio`：将共享见证者数量除以随机情况下的平均倒排列表长度。
- `MaxRatio`：在 `1..λ` 的多个子列表长度中选择最大的 `SimRatio`。
- `SimCorr`：集合相关分数。
- `MaxCorr`：在 `1..λ` 的多个子列表长度中选择最大的 `SimCorr`。
- `SimCos`：余弦分数。
- `MaxCos`：在 `1..λ` 的多个子列表长度中选择最大的 `SimCos`。

`Max*` 版本的作用是处理缓存列表长度或局部邻域尺度不一致的问题。某个对象可能在前 10 近邻尺度上证据最强，也可能在前 30 近邻尺度上证据最强。`Max*` 通过扫描子列表长度 `j ∈ [1, λ]`，选择最有显著性的尺度。

实验中主要展示 `SimCorr`、`MaxCorr`、`SimRatio`、`MaxRatio`。`SimCos` 和 `MaxCos` 因为与对应的相关分数几乎重合，被省略。

### 查询是否成功

论文不要求每次估计都返回结果。系统设定阈值 `φ`。只有分数不低于 `φ` 的对象才有资格进入估计结果。

若合格候选对象少于 `k` 个，则估计失败。系统可以回退到原始数据库或索引执行完整查询。该设计避免在缓存证据不足时强行返回低质量结果。

## 实现设计

### 缓存数据结构

论文需要维护两类数据。

**标准近邻列表**：

```text
Q(u, λ)
```

对每个缓存对象 `u`，保存它的前 `λ` 个近邻，按相关性排序。

**倒排近邻列表**：

```text
Q_C^-1(v, λ)
```

对任意对象 `v`，保存哪些缓存对象的近邻列表包含它。倒排列表中还保存 `v` 在对应缓存对象近邻列表中的排名。这样可以快速得到不同子列表长度 `j` 下的倒排集合 `Q_C^-1(v, j)`。

这类似搜索系统中的倒排索引，但倒排对象不是词项，而是“某对象出现在谁的近邻列表中”。

### 候选集合裁剪

若对每个查询 `v` 都扫描全体对象 `S`，成本会过高。论文利用一个事实：只有与查询共享至少一个见证者的对象才可能获得正分。

对查询 `v` 和子列表长度 `j`，只考虑：

```text
N(v, j) = ∪_{u ∈ Q_C^-1(v, j)} Q(u, j)
```

含义是：先找出把 `v` 放进前 `j` 个近邻的缓存对象 `u`，再把这些 `u` 的前 `j` 个近邻拿出来作为候选。其他对象没有共享见证者，直接忽略。

### 增量计数

论文用三个数组辅助计算：

- `RevIntCount[w]`：候选对象 `w` 当前累计的共享见证者数量。
- `VisitFlag[w]`：标记 `w` 是否在当前子列表长度 `j` 已访问。
- `SimValue[w]`：保存 `w` 当前最好的相似分数。

算法从 `j = 1` 扫描到 `λ`。每增加一个 `j`，只处理新进入倒排集合或标准近邻列表的对象，而不是重新计算所有交集。这样可同时得到 `SimInt_C,j(v,w)` 在所有 `j` 上的值，并支持 `MaxRatio`、`MaxCorr`、`MaxCos`。

最终步骤是把访问过的候选对象按分数排序，返回分数最高的对象列表。若结果不足 `k` 个，则缓存估计失败。

### 复杂度与空间要求

论文给出的计算成本为：

```text
O(λ · |Q_C^-1(v, λ)| + |N(v, λ)|)
```

其中 `|Q_C^-1(v, λ)|` 是查询对象的倒排见证者数量，`|N(v, λ)|` 是候选对象数。在平均情况下，论文将其近似为 `O~(λ^2)`。该成本成立的前提是倒排见证者数量不会随数据集规模线性增长。

为了让估计结果有意义，论文要求平均倒排列表长度不能太小：

```text
λ · |C| / |S|
```

该值表示一个对象平均被多少个缓存对象的近邻列表覆盖。若它太小，大量查询对象没有足够见证者，主动缓存会退化为 miss 或低质量估计。

该条件意味着主存需要为整个数据集提供一定覆盖，而不是只缓存少数高频对象。

## 实验设置

### 评估指标

论文使用两个主要指标。

**Hit rate（命中率）**：

传统被动缓存中，只有查询对象的结果列表被显式缓存才算命中。论文扩展主动缓存命中定义：若查询对象没有标准缓存列表，但它有非空倒排缓存列表，也算主动缓存可回答。若既没有标准列表，也没有倒排列表，则 miss。

**Recall（召回率）**：

对一次 top-k 查询，论文将缓存返回结果与完整数据库 top-k 结果比较，计算重叠比例。若缓存中显式保存了查询对象的 top-k 列表，recall 为 1。若 miss，recall 为 0。

论文还单独定义 `estimation recall`（估计召回率）：强制忽略查询对象可能已显式缓存的标准列表，只评估主动估计本身与真实 top-k 的重合程度。该指标用于衡量 CES 估计能力。

实验使用四个真实数据集：

| RCV1 | 802,352 | 新闻文档向量，向量夹角距离 |
| CT | 581,012 | UCI Cover Type 观测数据，欧氏距离 |
| KDD | 120,836 | KDD Cup 1999 入侵事件样本，欧氏距离 |

论文使用 `SASH`（论文采用的近似相似搜索结构）为每个数据集计算 100-NN 列表。SASH 不是 HNSW。

### 缓存构造

实验从数据集中均匀随机选择一部分对象进入标准缓存。缓存比例在不同实验中变化，例如从 2.5% 到 100%。

对每个缓存对象，保存其标准近邻列表 `Q(u, λ)`，再构造对应倒排缓存。随后将数据集中每个对象都作为一次 k-NN 查询。

实验主要比较：

- 传统被动缓存；
- CES 主动缓存的 `SimCorr`、`MaxCorr`、`SimRatio`、`MaxRatio` 变体。

## 实验结果

### 命中率

Fig. 3 比较 ALOI 和 RCV1 上不同缓存比例下的命中率。主动缓存的命中率明显高于传统被动缓存，并且随 `λ` 增大快速上升。

ALOI 上，在较小缓存比例下，`λ = 30/50/100` 的主动缓存命中率已明显高于传统缓存。RCV1 上也呈现相同趋势，`λ = 30` 比 `λ = 10` 命中率更高。

原因是主动缓存不要求查询对象本身被缓存。只要查询对象出现在某些缓存对象的近邻列表中，就可能被倒排缓存覆盖。`λ` 越大，每个缓存对象覆盖的对象越多，倒排缓存覆盖范围越广。

### 考虑空间后的命中率

Fig. 4 用缓存占用的 MB 数作为横轴，比较 ALOI、RCV1、CT 和 KDD。

论文指出，CES 需要存储倒排列表，因此比传统缓存占用更多空间。若每个对象 ID 用 4 字节表示：

- 传统缓存约需 `4λ` 字节/缓存对象；
- `SimCorr` 和 `SimRatio` 主动缓存约需 `8λ` 字节/缓存对象；
- `MaxCorr` 和 `MaxRatio` 因需保存排名信息，约需 `12λ` 字节/缓存对象。

即便考虑额外空间，在缓存规模低于全数据约三分之一时，主动缓存在四个数据集上的可回答查询比例仍显著高于传统缓存。

### 缓存命中时的 recall

Fig. 5 评估 `k = λ = 30` 时，主动缓存命中查询的平均 recall。四个数据集上，`SimCorr`、`MaxCorr`、`SimRatio`、`MaxRatio` 都能达到较高 recall，并随缓存比例增加而提高。

论文给出一个明确例子：ALOI 上缓存 25% 对象时，主动缓存变体可回答约 98% 查询，平均 recall 达到 0.8 以上。相同条件下，传统被动缓存只能回答 25% 查询，但这些命中的 recall 为 1。

这个结果体现出主动缓存的权衡：牺牲部分结果精确性，换取更大查询覆盖率和更少回源查询。

### 查询结果大小与列表长度

Fig. 6 在 ALOI 上使用 `SimRatio`，设置 `k = λ = 10/30/50/100`。结果显示，不同 `k = λ` 设置下 recall 曲线差异不大，主要仍由缓存比例决定。

Fig. 9 固定 `k = 30`，改变缓存列表长度 `λ`。结果显示 `λ = k = 30` 时效果最好。若 `λ` 小于 `k`，缓存列表包含的相关对象不足，估计 recall 明显下降。若 `λ` 大于 `k`，列表中包含更多与 top-30 无关的对象，`SimRatio` 和 `SimCorr` 下降更明显；`MaxRatio` 和 `MaxCorr` 因可在不同子列表长度上取最大值，对较大 `λ` 更稳定。

### 估计能力与见证者数量

Fig. 7 强制忽略显式缓存的标准列表，只评估主动估计本身。ALOI 上，缓存 25%、`k = λ = 30` 时，估计 recall 随查询对象倒排列表大小增加而上升。

当查询对象只有很少见证者时，估计不稳定；见证者数量增加后，四种方法的 recall 都保持较高水平。其中 `MaxRatio` 和 `SimRatio` 在多数见证者数量范围内略优于相关系数版本。

该实验支持 CES 的关键假设：倒排见证者越多，缓存越有能力推断查询对象的近邻。

### 分数阈值

Fig. 8 在 ALOI 上考察分数阈值。系统只在估计结果中每个对象都超过指定阈值时返回结果。阈值越高，返回结果的平均 recall 越高。

这说明 CES 分数不仅可用于排序，还可作为结果可靠性的过滤信号。系统可以用阈值控制“少回源但可能较低 recall”和“多回源但结果更可靠”之间的取舍。

### 噪声鲁棒性

Fig. 10 将部分缓存近邻列表替换为随机生成的噪声列表。随着噪声比例从 0% 增加到 100%，估计 recall 近似线性下降。

论文认为该结果说明 CES 对一定比例噪声具有容忍度。只要缓存中仍有足够真实近邻列表，共享邻居信号仍能维持较高 recall。若全部列表都是噪声，方法自然退化。

### 变长缓存列表

Fig. 11 左图让一部分标准缓存列表长度在 1 到 100 之间随机变化，其余保持 30。缓存比例为 25%，查询为 top-30。

结果显示，`MaxCorr` 和 `MaxRatio` 在变长列表比例升高时更稳定，`SimCorr` 和 `SimRatio` 有更明显下降。这符合设计预期：`Max*` 方法可在不同子列表长度上选择最显著尺度，更能适应缓存列表长度不一致。

Fig. 11 右图在所有标准缓存列表长度都随机分布于 1 到 100 时改变 `k`。实验显示 `k` 在 30 到 40 附近表现最好。论文解释为：当 `λ > k` 时，缓存列表中有较多对 top-k 无关的对象；当 `λ < k` 时，缓存列表缺少应进入结果的对象。`k = 30..40` 在该实验设置下取得两者之间的折中。

## 论文贡献

1. 将主动缓存从布尔查询扩展到 top-k 相似查询。
2. 提出只用缓存近邻列表和倒排近邻列表估计未缓存查询结果的方法。
3. 用共享邻居和显著性校正处理缓存覆盖、列表长度和倒排列表大小带来的偏差。
4. 给出可实现的增量算法，避免扫描全体数据对象。
5. 实验显示，在随机选择缓存对象的情况下，主动缓存可显著提高可回答查询比例，并在多数命中场景保持较高 recall。

## 局限

1. 论文评估的是应用级缓存命中率和 recall，没有报告查询延迟、吞吐、CPU cache miss、内存带宽或硬件计数器。
2. 实验使用预计算 100-NN 列表和 SASH 近似搜索结构，不是 HNSW，也不是现代向量数据库实现。
3. 缓存对象随机选择。论文没有系统研究真实查询分布、热点对象、在线缓存替换策略或工作负载随时间变化。
4. 主动缓存返回的是估计 top-k 结果，不保证与完整检索结果一致。它适合允许近似答案的场景，不适合必须精确返回索引结果的服务。
5. 方法需要为数据集提供足够倒排覆盖。若 `λ · |C| / |S|` 太小，大量查询缺少见证者，主动缓存无法发挥作用。
6. 论文没有讨论构建和维护倒排缓存的增量更新成本，也没有讨论数据插入、删除和向量更新。

## 对当前 HNSW/Chiplet 研究的启发

### 可借鉴内容

论文证明了一个可迁移的事实：相似对象的近邻列表存在可利用的重叠关系。对 HNSW batch 查询而言，相似 query 也可能访问重叠的图节点、邻接表和向量数据。因此，query 分组或调度可以考虑“共享邻域”信号。

可借鉴方向包括：

- 用少量预搜索或历史 trace 估计 query 之间的邻域重叠；
- 将共享节点较多的 query 放到同一 CCD 或同一时间窗口执行；
- 将“倒排见证者数量”转化为 query 相似度或复用潜力估计；
- 用阈值控制只对高置信相似 query 做局部化调度，避免错误分组。

### 不能直接迁移的内容

论文中的 cache 是应用级结果缓存，不是 L3 cache。CES 命中率提升不能推出 HNSW 会减少 L3 miss，也不能推出同 CCD 调度必然加速。

论文缓存的是结果列表和倒排关系，而 hnswlib 查询主开销通常来自第 0 层图遍历中的邻接表读取、向量距离计算和 visited list 维护。二者的数据结构和访问粒度不同。

论文估计的是查询答案，可能降低结果精确性。当前若研究 HNSW 调度或 cache locality，通常不应改变搜索语义和 recall。更合适的迁移方式是把 shared-neighbor 信息作为调度特征，而不是用 CES 替代 HNSW 搜索。

### 与类似 query 调度的关系

该论文与 `Enhancing Similarity Search Throughput by Dynamic Query Reordering` 都利用“相似 query 共享访问内容”的思想，但目标不同：

- Dynamic Query Reordering 调整查询执行顺序，让连续查询复用索引分区缓存。
- CES 主动缓存直接用已有近邻列表估计查询结果，减少回源执行。

对 chiplet 研究而言，前者更接近请求调度，后者更接近复用信号构造。CES 的倒排见证者思想可用于识别相似 query，但其实验结果不能作为硬件 locality 收益证据。

## 结论

论文的核心价值在于提出一种“覆盖式缓存”思路：缓存不只保存未来可能重复请求的完整结果，还可以保存一批代表性对象的近邻关系，用共享邻居证据为未缓存查询生成近似答案。

对当前 HNSW/chiplet 方向，该论文可作为相似 query 共享邻域的背景材料，但不能作为 HNSW 索引优化或分片 L3 优化的直接证据。若后续使用该思想，应把 CES 降级为 query 相似度估计或调度特征来源，并用 HNSW trace、recall、QPS、L3 miss、DRAM 访问和 CCD 放置实验重新验证。
