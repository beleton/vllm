# HNSW 原论文解读

**一句话概述**：论文提出 HNSW（Hierarchical Navigable Small World，层次化可导航小世界图），用多层近邻图（proximity graph）组织向量或一般度量空间中的对象。查询从稀疏顶层入口点（entry point）开始贪婪下探，在第 0 层用 `efSearch` 控制搜索宽度的最佳优先搜索（best-first search）找近邻；构建时通过随机层级、`M/Mmax0` 连接上限和邻居多样化启发式提升鲁棒性。实验显示 HNSW 在多个向量和一般度量空间数据集上优于 NSW、FLANN、Annoy、VP-tree、FALCONN 等开源方法。

---

## 背景：近似最近邻与图搜索基础

### K-NNS 与 K-ANNS

**K-NNS**（K-Nearest Neighbor Search，K 近邻搜索）：给定查询对象 $q$ 和距离函数 $d(\cdot,\cdot)$，从数据集 $X=\{x_1,x_2,\ldots,x_N\}$ 中找出距离 $q$ 最近的 $K$ 个对象。朴素方法是计算 $q$ 与所有 $N$ 个对象的距离再排序，复杂度 $O(N)$，在大规模高维数据上不可行。

**K-ANNS**（Approximate K-Nearest Neighbor Search，近似 K 近邻搜索）：允许返回结果中存在少量错误（即返回的近邻不全是真正的最近邻），用 **recall（召回率）** 衡量质量：

$$\text{recall} = \frac{|\{\text{找到的真正近邻}\}|}{K}$$

### Proximity graph 与 NSW

**Proximity graph（近邻图）** 将数据对象作为节点，边连接距离较近的对象。查询时从入口点出发，沿着使距离变小的边移动。图搜索面临的困境是：

- **高维数据**：Delaunay 图（一种保证贪婪搜索总能找到精确最近邻的特殊近邻图，可看作近邻图的"黄金标准"）的节点度数随维度指数增长，无法高效近似
- **低维或聚类数据**：普通 k-NN 图容易出现 **power-law scaling（幂律缩放）**——搜索步数随数据量呈 $O(N^\alpha)$ 增长，性能退化严重

**NSW（Navigable Small World，可导航小世界图）** 利用小世界网络的长短边混合结构进行搜索。NSW 的问题是图中不同尺度的边没有显式分层，所有搜索都在单层图完成：

- 搜索路由分为两阶段：zoom-out（从小度节点爬到 hub，此阶段容易陷入局部最优）和 zoom-in（从 hub 向目标逼近）。详见下方「NSW 搜索的两个阶段」一节。
- 最终复杂度是 $O((\log N)^k)$（多对数级），而非理论最优的 $O(\log N)$

## 基础：图、边、向量查询

### 图的节点和边
- **节点**：数据集中的向量本身。如果数据集有 100 万个 128 维 SIFT 特征向量，图中就有 100 万个节点。
- **边**：两个节点之间的"近邻关系"。如果节点 A → B 有一条边，意味着 B 是 A 的近邻之一。

边的具体来历取决于构建方式。以 NSW 为例：每插入一个新向量 $q$，先在已有图中搜出离 $q$ 最近的 $M$ 个向量，然后在 $q$ 和这 $M$ 个向量之间建立**双向边**。换句话说，边记录的是"构建时发现这两个点彼此接近"这一事实。整张图就是所有近邻关系的集合。

### 向量查询怎么变成图搜索？

下面是核心直觉。假设平面上有一组二维点，已经按上述规则建好了图：
```
数据集中的点（即图中的节点）:

    B(2,8)
                          
         A(2,5)        E(7,4)
                        
    C(1,3)        D(5,2)
```

现在来了一个**不在数据集中的查询向量** $q(6,5)$，要找数据集中离它最近的点。图搜索的过程如下：
```
Step 1: 从入口点 A(2,5) 出发。
        A 在图中连接了 B, C, D。分别计算它们到 q 的距离：
          d(B,q) = 5
          d(C,q) = 5.4
          d(D,q) = 3.2  ← 最近！
          d(A,q) = 4
        D 比 A 更接近 q → 沿着边跳到 D

Step 2: 当前在 D(5,2)。
        D 的邻居中有 E(7,4)：
          d(E,q) = 1.4  ← 比 D 自身更近！
        → 跳到 E

Step 3: 当前在 E(7,4)。
        检查 E 的所有邻居，没有任何比 d(E,q)=1.4 更近。
        → 搜索停止。E(7,4) 就是找到的最近邻。
        （如果 K>1，就返回途经的所有节点中离 q 最近的 K 个。）
```

整个过程就是**反复执行一个操作**：从当前节点出发，看它的所有邻居中有没有比当前更接近查询的点，有就跳过去，没有就停。图的作用就是告诉算法"每个节点旁边还有谁"——把暴力扫描 $O(N)$ 变成了沿边跳跃式逼近。

> 实际搜索比这复杂一点（SEARCH-LAYER 维护一个候选集而非单纯贪心），但核心逻辑完全一样：**沿着近邻边向查询目标移动**。

### NSW 具体是什么？

NSW（Navigable Small World，可导航小世界图）是 HNSW 的前身——**一个没有分层的、单层的近邻图**。

**NSW 的构建**异常简单：

1. 把数据集中的向量**随机打乱顺序**
2. 逐个插入。每插入一个新元素，用当前图搜索离它最近的 $M$ 个点，双向连接
3. 没有层级、没有连接数上限（$M_{\text{max}0} = \infty$）

**为什么随机顺序插入就能产生"可导航"的图？** 这是 NSW 最妙的洞见：

```
最早插入的节点：
  彼此连接形成初始"骨架"。
  随着越来越多节点插入，它们不断被新节点选为近邻，
  逐渐积累大量连接 → 成为 hub（枢纽节点）

后插入的节点：
  连接数较少，围绕在 hub 周围

最终形成的图结构：
  
         [hub1] ─────── 长边 ─────── [hub2]
        /  |  \                        /  |  \
     node node node              node node node
     (局部短边)                    (局部短边)
```

- **短边**（hub ↔ 周边节点）：负责本地区域的精细分辨
- **长边**（hub ↔ hub）：负责跨区域大跳转——正因为早期 hub 节点来自随机顺序，它们分散在数据空间各处，彼此连接就形成了跨区域的"高速公路"

这就是 **"小世界"（Small World）** 的含义：尽管图很大，任意两点间只需极少的跳数就能到达——类似于社交网络中的六度分隔。你大多认识本地的人（短边），但总有几个远方的朋友（长边），通过他们可以在很少的中间人内联系到地球上任何人。

#### NSW 搜索的两个阶段：zoom-out 与 zoom-in

论文将 NSW 中一次贪婪搜索的路由过程分为两个阶段，这是理解"为什么需要分层"的关键：

```
                    查询 q
                      ↑
                      |  【zoom-in 阶段】
                      |  边越来越短，度数越来越小
                      |  精细逼近目标
                      |
                   [hub]  ← 枢纽节点，度数最大，边的覆盖半径最广
                    /|\
                   / | \
                  /  |  \    【zoom-out 阶段】
                 /   |   \   从小度节点出发，沿路节点度数越来越大
                /    |    \  边的跨度越来越长，像镜头"拉远"
               /     |     \
           [起点]   ...    ...
          (随机节点, 度数小)
```

**阶段 1 — zoom-out（拉远）**：搜索从一个随机节点出发。通常这个节点度数很小，它的边只覆盖局部的邻近区域。随着贪婪搜索沿着"离查询更近"的方向移动，路径上的节点度数越来越大——你逐渐走到了 hub 节点上。在这个过程中，节点之间的边跨度（特征半径，characteristic radius）不断增大，就像镜头在"拉远"（zoom out），从局部的细节视野扩展到更大范围的空间结构。

**这个阶段的危险**：zoom-out 阶段路径上的节点度数仍然较小，意味着每一步的可选方向有限，容易走到一个"假局部最优"——当前节点的所有邻居都比它离查询更远，但实际上只是因为你还没走到 hub，被局部地形困住了。

**阶段 2 — zoom-in（逼近）**：一旦到达一个度数足够大的 hub 节点，其边的覆盖半径已经达到了"查询距离"的尺度。此后，搜索沿着越来越短的边逐步逼近查询目标——节点度数越来越小，边越来越短，就像镜头在"拉近"（zoom in）聚焦到目标细节上。

**一个重要的经验发现**：如果搜索能**直接从最高度数的 hub 出发**（跳过 zoom-out），搜索质量会显著提升，尤其在低维数据上。NSW 中最早插入的节点正是这样的 hub——它们的度数最高。HNSW 将这一发现系统化：总是从全局最高层节点（天然的最高度数节点）作为入口点，通过多层结构将 zoom-in 阶段分解到不同层中。

#### NSW 的问题

所有边混在同一层。搜索的 zoom-out 阶段中，路径上节点的平均度数随 $\log N$ 增长 → 每一步要检查的邻居数越来越多 → 跳数（$\log N$）× 平均度数（$\log N$）→ $O((\log N)^2)$，即**多对数复杂度**。

HNSW 的改进就是**把长短边显式分层**——上层只放长边（节点少、度数有上限）、下层放短边——使得每步检查的邻居数变成常数，从而把复杂度压到 $O(\log N)$。

## 研究问题

论文要解决三个核心问题：

1. **全图结构索引**：不依赖粗量化器（coarse quantizer，指 kd-tree、LSH、乘积量化等辅助预聚类/哈希结构），构建一个完全基于图的通用 ANNS 索引。
2. **降低路由退化**：将 NSW 从多对数复杂度（$O((\log N)^k)$）降到接近对数复杂度（$O(\log N)$），缓解在低维、聚类和大规模数据上的性能退化。
3. **高召回率区间（high recall regime）保持连通性**：所谓"高召回率区间"指的是 recall > 0.9 甚至 > 0.99 的严格工况——此时搜索不能遗漏任何近邻，对图的全局连通性要求极高。简单取最近的 M 个邻居做连接容易导致簇内边过多、跨簇边不足，使搜索在簇边界"卡住"。

## 核心思想：为什么需要"层次化"？

### 从 NSW 的困境出发

NSW 的单个贪婪搜索在 N 个节点的图中，平均跳数和路径上节点的平均度数都随 $\log N$ 增长，两者相乘得到 $O((\log N)^2)$ 的距离计算量——这就是**多对数复杂度**的来源。

HNSW 的核心想法是：**把不同长度尺度的边分离到不同层中**。上层只有长边（"zoom-in"阶段），下层有短边（精细搜索）。这样每层只需检查常数数量的连接，与总数据量无关，从而实现 $O(\log N)$ 复杂度。

### 与 Skip List 的类比

HNSW 可以视为 **概率跳表（skip list）在近邻图上的推广**：

- Skip list：链表 + 随机层级 → $O(\log N)$ 查找
- HNSW：近邻图 + 随机层级 → $O(\log N)$ 近邻搜索

Skip list 中 50% 的节点出现在第 1 层，25% 出现在第 2 层……以此类推。HNSW 用指数衰减概率分布决定每个节点的最高层：

$$l = \lfloor -\ln(\text{uniform}(0,1)) \cdot m_L \rfloor$$

其中 $m_L$ 是归一化因子。$m_L$ 越大，高层节点越多；推荐 $m_L = 1/\ln(M)$，对应 skip list 参数 $p=1/M$。

## 图结构：多层近邻图剖面

```
层 3:  [●]                         ← 仅 1 个节点（入口点），图稀疏
          \
层 2:  [●]───[●]                    ← 少数节点，边长、跨度大
            \
层 1:  [●]───[●]───[●]───[●]       ← 节点增多，边中等长度
              \
层 0:  [●]──[●]──[●]──[●]──[●]──[●] ← 全量节点，边短、密度高
             [●]──[●]──[●]──[●]
```

**关键性质**：
- 第 0 层（底层）包含数据集中的**所有节点**，边短而密集，负责局部精细搜索
- 每升高一层，节点数指数衰减，边变长、变稀疏，负责"大跨步"导航
- 节点出现在第 $l$ 层意味着它也出现在所有 $<l$ 的层
- 最高层的唯一节点就是全局入口点（entry point）

## 算法详解

### Algorithm 1：插入（INSERT）

```
INSERT(hnsw, q, M, Mmax, efConstruction, mL)

1   W ← ∅                           // 当前找到的最近邻集合
2   ep ← 获取 hnsw 的入口点
3   L ← ep 的层级                    // hnsw 当前最高层
4   l ← ⌊-ln(uniform(0,1))·mL⌋     // 新元素 q 的随机最高层
5   for lc ← L … l+1                // 阶段 1: 在比 l 高的层中贪婪下探
6       W ← SEARCH-LAYER(q, ep, ef=1, lc)
7       ep ← W 中离 q 最近的元素      // 更新下一层的入口点
8   for lc ← min(L, l) … 0          // 阶段 2: 在 l 及以下层建立连接
9       W ← SEARCH-LAYER(q, ep, efConstruction, lc)
10      neighbors ← SELECT-NEIGHBORS(q, W, M, lc)
11      在层 lc 中建立 neighbors ↔ q 的双向连接
12      for each e ∈ neighbors       // 剪枝邻居的邻接表
13          eConn ← e 在层 lc 的邻接表
14          if |eConn| > Mmax        // 第 0 层用 Mmax0
15              eNewConn ← SELECT-NEIGHBORS(e, eConn, Mmax, lc)
16              更新 e 在层 lc 的邻接表为 eNewConn
17      ep ← W
18  if l > L                         // 新节点层级刷新最高记录
19      设置 hnsw 的入口点为 q
```

**分阶段解读**：

**阶段 1（第 5-7 行）**：新节点 $q$ 最高层为 $l$。在比 $l$ 高的层（$l+1$ 到 $L$）中，$q$ 不会出现在这些层，所以只做**导航**——每层用 `ef=1` 做纯贪婪搜索，找到离 $q$ 最近的入口点，传给下一层。`ef=1` 意味着每层只保留 1 个最近邻，即"一条路走到黑"的贪婪下降。

**阶段 2（第 8-17 行）**：从 $\min(L, l)$ 层向下直到第 0 层，$q$ 在这些层中**实际存在**，需要建立连接。此时 `ef` 从 1 提升到 `efConstruction`（典型值 100-400），意味着每层保留一个更大的候选集，搜索更充分。找到候选集后，用邻居选择算法（Algorithm 3 或 4）从中挑选 M 个邻居建立双向边。

**为什么"双向连接"很重要？** 如果只建单向边，新节点可能成为"孤岛"——别的节点没有指向它的边，后续搜索就找不到它。

**为什么需要剪枝（第 12-16 行）？** 连接是双向的：$q$ 连接了 $e$，$e$ 的度数也增加了。如果 $e$ 的度数超过了 $Mmax$（或第 0 层的 $Mmax0$），就要对 $e$ 的邻接表重新执行邻居选择，裁掉多余的连接。这保证了每层每个节点的度数有上界，避免图无限膨胀。

### Algorithm 2：层内搜索（SEARCH-LAYER）

这是 HNSW 最核心的算法。它不是简单的"走到无路可走"，而是一种**带宽度限制的最佳优先搜索（best-first search with bounded width）**：

```
SEARCH-LAYER(q, ep, ef, lc)

1   v ← {ep}        // 已访问节点集合
2   C ← {ep}        // 候选队列（按距离排序的优先队列）
3   W ← {ep}        // 当前结果集（按距离排序，最大容量 ef）
4   while |C| > 0
5       c ← 从 C 中弹出离 q 最近的元素
6       f ← W 中离 q 最远的元素
7       if distance(c, q) > distance(f, q)
8           break    // 所有候选都比当前结果集最远元素更远 → 终止
9       for each e ∈ c 在层 lc 的邻居
10          if e ∉ v
11              v ← v ∪ {e}
12              f ← W 中离 q 最远的元素
13              if distance(e, q) < distance(f, q) or |W| < ef
14                  C ← C ∪ {e}
15                  W ← W ∪ {e}
16                  if |W| > ef
17                      从 W 中移除离 q 最远的元素
18  return W
```

**算法核心机制解读**：

**两个队列的分工**：
- **候选集 C**（优先队列，按距离排列）：所有"等待探索"的节点。每次从中取出最近的节点，探索其邻居
- **结果集 W**（优先队列，容量 ef）：当前找到的离查询最近的 ef 个节点。既是"目前最佳答案"，也是搜索的"边界"——任何比 W 中最远元素还远的候选都可以安全丢弃

**终止条件（第 7-8 行）**：这是算法优雅的精髓。当候选集中最近的节点都比结果集中最远的节点更远时，意味着所有未探索的候选都不如已有结果好，搜索可以提前终止。这避免了在无关区域浪费距离计算。

**新邻居的准入（第 13-15 行）**：新探索到的邻居 $e$ 需要满足两个条件之一才能加入候选集：
1. $|W| < ef$：结果集还没满，来着不拒
2. $\text{distance}(e, q) < \text{distance}(f, q)$：$e$ 比结果集中最远的 $f$ 更近

**搜索宽度 $ef$ 的作用**：

$$ef = 1 \quad \rightarrow \quad |W| = 1 \quad \rightarrow \quad \text{等价于纯贪婪搜索（greedy search），最快但可能陷入局部最优}$$

$$ef \gg K \quad \rightarrow \quad |W| \text{ 大} \quad \rightarrow \quad \text{搜索覆盖面广，recall 高但耗时长}$$

在第 0 层以下（即第 0 层本身），$ef$ 就是 `efSearch`（查询时）或 `efConstruction`（构建时）。在上层，$ef=1$ 就够了——上层的作用只是"导航到正确区域"，不需要精细搜索。

### Algorithm 3 vs Algorithm 4：两种邻居选择策略

#### Algorithm 3：简单邻居选择

```
SELECT-NEIGHBORS-SIMPLE(q, C, M)
    return C 中离 q 最近的 M 个元素
```

直接取距离最近的 M 个。问题在于：在聚类数据上，最近邻往往集中在同一簇内，导致图缺乏跨簇连接。

#### Algorithm 4：启发式邻居选择

```
SELECT-NEIGHBORS-HEURISTIC(q, C, M, lc, extendCandidates, keepPrunedConnections)

1   R ← ∅                               // 结果集
2   W ← C                               // 工作队列（候选集副本）
3   if extendCandidates                  // 扩展候选集：加入候选的邻居
4       for each e ∈ C
5           for each eadj ∈ e 在 lc 层的邻居
6               if eadj ∉ W
7                   W ← W ∪ {eadj}
8   Wd ← ∅                              // 被丢弃的候选队列
9   while |W| > 0 and |R| < M
10      e ← 从 W 中弹出离 q 最近的元素
11      if e 比 R 中任何元素都更接近 q   // ← 核心判据
12          R ← R ∪ {e}                 // 接受：e 的方向以前没覆盖过
13      else
14          Wd ← Wd ∪ {e}              // 拒绝：该方向已有代表
15  if keepPrunedConnections            // 补充被丢弃的候选
16      while |Wd| > 0 and |R| < M
17          R ← R ∪ 从 Wd 中弹出离 q 最近的元素
18  return R
```

**核心判据（第 11 行）解读**：

"$e$ 比 $R$ 中任何元素都更接近 $q$"——这句话看似平凡，实则精巧。用论文 Fig. 2 的场景说明：

```
数据集：两个孤立的簇 Cluster 1 和 Cluster 2

         Cluster 1                    Cluster 2
        ●     ●     ●              ●     ●     ●
          ●           ●              ●           ●
            ●    [q]  ●            ●    [e2]   ●
              ●     ●              ●     ●     ●

q 是插入到 Cluster 1 边界上的新节点。
```

**不用启发式（Algorithm 3）**：q 的所有 M 个最近邻都在 Cluster 1 内部 → q 只与 Cluster 1 的节点建立连接 → 图在两个簇之间"断开" → 搜索无法从一个簇跳到另一个簇。

**用启发式（Algorithm 4）**：按距离从近到远检查候选。当检查到 e2（Cluster 2 的边界节点）时，虽然 e2 比 Cluster 1 内部的节点更远，但 e2 比 R 中**任何已选节点都更接近 q**（因为从 q 到 Cluster 2 的方向还没有代表），所以 e2 被选为邻居 → 图保持了跨簇连通性。

本质上，这个启发式试图**选择方向多样化的邻居**：每个被选的邻居都代表了从 q 出发的一个"新方向"，避免多个邻居挤在同一方向。论文指出，当候选集足够大时，该启发式可以得到**相对邻域图（Relative Neighborhood Graph）**——Delaunay 图的一个最小子图，仅用节点间距离信息就能推导。

### Algorithm 5：K 近邻查询（K-NN-SEARCH）

```
K-NN-SEARCH(hnsw, q, K, ef)

1   W ← ∅
2   ep ← 获取 hnsw 的入口点
3   L ← ep 的层级
4   for lc ← L … 1                   // 上层：ef=1 纯贪婪
5       W ← SEARCH-LAYER(q, ep, ef=1, lc)
6       ep ← W 中离 q 最近的元素
7   W ← SEARCH-LAYER(q, ep, ef, lc=0) // 第 0 层：用 ef 控制宽度
8   return W 中离 q 最近的 K 个元素
```

查询流程与插入一个 $l=0$ 的元素几乎相同，区别在于：
- 第 0 层的候选集不用于建立连接，而是**直接作为搜索结果**
- 最终从结果集 W 中取最近的 K 个返回

**搜索过程可视化**：

```
层 3:  ep ──────────→ ● (入口点)
                      │
层 2:                 ● ────→ ●
                              │
层 1:                         ● ────→ ● ────→ ●
                                          │
层 0:  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
       ░  ●──●──●    ●──●      ░  ●──[q]              ░
       ░    ●  ●    /  ●  \    ░  /  ↑ 目标查询        ░
       ░   ●● ●●   ●   ●  ●   ░ ●  ●                  ░
       ░   ●   ●  ●    ●  ●   ░ 搜索从 ep 在第 0 层     ░

       ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░

→ 表示上层贪婪路径（ef=1，每层一步到位）
```

## 参数选择指南

### mL（层级衰减因子）

- **作用**：控制高层节点密度。$l = \lfloor -\ln(\text{uniform}(0,1)) \cdot m_L \rfloor$
- **推荐值**：$m_L = 1 / \ln(M)$
- **直觉**：对应 skip list 中每层节点数是上一层的 $1/M$，保证层间邻居重叠最小
- **过大**：高层节点多、每层跳数少但层数多（整体搜索路径可能更长）
- **过小**：高层太稀疏（趋近 NSW 单层结构，失去分层优势）

### M（每层邻居数）

- **作用**：构建时从候选集中选取的邻居数量，直接影响连通性
- **推荐范围**：5-48
- **直觉**：M 小 → 图稀疏 → 内存小 → 低召回率场景较好；M 大 → 图密集 → 高召回率场景更好但内存更大
- **低维数据**：较小 M（如 6-12）即可
- **高维数据**：需要较大 M（如 20-48）

### Mmax 与 Mmax0（最大连接数）

- **Mmax**（第 1 层及以上）：通常等于 M，高层节点少、不需要太大
- **Mmax0**（第 0 层）：推荐 $2 \times M$
- **为什么第 0 层要翻倍？** 第 0 层包含所有节点且负责最终精确搜索，更大的连接上限允许更充分的局部连接。论文实验显示 Mmax0=M 会导致高召回率区间性能严重下降（Fig. 6），而 Mmax0 > 2M 会带来额外内存开销而无性能收益

### efConstruction（构建阶段搜索宽度）

- **作用**：插入新节点时第 0 层搜索的宽度
- **推荐值**：使构建召回率接近 1（约 0.95 即可）
- **典型值**：100-400
- **权衡**：efConstruction 越大 → 图质量越好 → 查询越快，但构建时间越长。论文 Fig. 10 显示 efConstruction=100 在 10M SIFT 上约 3 分钟可构建可用索引

### efSearch / ef（查询阶段搜索宽度）

- **作用**：查询时第 0 层搜索的宽度
- **典型值**：1 到数千，取决于目标召回率
- **权衡**：ef 越大 → 召回率越高 → 查询越慢
- **选择逻辑**：在线服务通常从较低 ef 开始，按需增加以满足召回率要求

## 复杂度的严格分析

### 搜索复杂度为何是 $O(\log N)$？

在以下两个假设下可以严格证明：

**假设 1**：每层都构造了精确 Delaunay graph（保证贪婪搜索在该层找到最近邻）。

**假设 2**：Delaunay graph 的节点平均度数在大数据集下有常数上界 $C$（在欧氏空间中对随机数据成立）。

在这两个假设下：

- 层级与数据空间位置无关，搜索在某一层遇到属于更高层的节点的概率为 $p = e^{-m_L}$
- 搜索在第 $s$ 步仍未到达目标的概率 ≤ $e^{-s \cdot m_L}$
- **每层期望步数** ≤ $\sum_{s=1}^{\infty} e^{-s \cdot m_L} = \frac{1}{1 - e^{-m_L}}$（几何级数求和），与数据集大小无关

→ 每层搜索步数有一个**常数上界** $S = \frac{1}{1 - e^{-m_L}}$

→ 每层距离计算次数 ≤ $C \cdot S$（常数 × 常数 = 常数）

→ 而期望层数为 $O(\log N)$（指数衰减概率分布的性质）

→ **总距离计算次数 = $O(\log N)$**

### 近似 Delaunay graph 的影响

实际上 HNSW 使用**近似边**（固定的 M 个邻居 + 启发式选择），不是精确 Delaunay graph。这意味着贪婪搜索可能陷入局部最优。因此 HNSW 在第 0 层引入了**回溯机制**（通过 ef > 1 的 best-first search）。

论文通过实验（Fig. 11, d=4 随机数据）表明：**达到固定召回率所需的 ef 值随数据规模增长而饱和**（即回溯所需的额外计算量不随 N 无限增长），因此近似带来的开销只是一个加法常数项，不改变 $O(\log N)$ 的整体复杂度缩放。

### 高维数据的注意事项

Delaunay graph 的平均度数随维度**指数增长**。在高维（如 d=128）下，"度数有常数上界"的假设不成立。此时 HNSW 的搜索复杂度理论上可能退化。但论文的实证结果显示 HNSW 在实践中仍然有效——这主要是因为实际高维数据（如 SIFT）的内在维度往往低于显式维度，且 M 的固定限制了每条搜索路径的度数。

## 退化形式：HNSW 的参数空间

论文指出，参数取值可使 HNSW 退化到其他已知结构：

| 参数设置 | 退化结果 | 复杂度 |
|---|---|---|
| $m_L = 0$, $M_{\text{max}0} = M$ | 有向 k-NN 图（directed k-NN graph，每个节点指向最近 k 个邻居） | 幂律 $O(N^\alpha)$ |
| $m_L = 0$, $M_{\text{max}0} = \infty$ | NSW（单层、无度数上限） | 多对数 $O((\log N)^k)$ |
| $m_L > 0$, $M_{\text{max}0} = 2M$（推荐） | HNSW（多层、有度数上限） | 对数 $O(\log N)$ |

这清晰地说明：**层级结构（$m_L > 0$）和第 0 层度数上限（$M_{\text{max}0}$）是 HNSW 区别于 NSW 和 k-NN graph 的核心机制**。

## 实验结果要点

### 与 NSW 的对决（Fig. 12）

在 d=4 随机数据上，HNSW 相比 NSW 大幅减少了距离计算量，特别是在高召回率区间（recall > 0.95）。在 d=8 固定 recall=0.95 的扩展实验中，HNSW 的距离计算随数据量增长不劣于对数级（NSW 则是多对数级）。

### Vector 数据集对比（Fig. 13）

| 数据集 | 规模 | 维度 | 距离 | HNSW 表现 |
|---|---|---|---|---|
| SIFT | 1M | 128 | L2 | 全面优于 FLANN, Annoy, VP-tree |
| GloVe | 1.2M | 100 | cosine | 领先 |
| CoPhIR | 2M | 272 | L2 | 领先 |
| Random | 30M | 4 | L2 | 高召回区间优于 Annoy |
| DEEP | 1M | 96 | L2 | 领先 |

### 一般度量空间（Fig. 14）

在通用度量空间（非必须满足欧氏距离公理）数据集上，HNSW 在所有测试集上优于 NSW，Wiki-8 上距离计算量降低约 3 个数量级。这支撑了论文"通用度量空间索引"的定位。

### PQ 方法对比（Table 3, Fig. 15）

200M SIFT 子集上，HNSW vs Faiss `OPQ+IMI+PQ`：
- **搜索更快、构建更快、精度更高**
- **峰值内存更大**（HNSW 存完整向量，PQ 存压缩码）
- 结论：HNSW 用内存换精度和速度；内存受限场景下压缩方法仍有价值

### 构建并行性（Fig. 9-11）

- 构建可高效并行，线程数增加后构建时间下降，对索引质量无可测影响
- 在 4 路 Xeon E5-4650 v2 上，10M SIFT 用 `efConstruction=100` 约 3 分钟可构建可用索引

## 边界与局限

1. **复杂度理论不完全在高维成立**：$O(\log N)$ 的分析依赖 Delaunay graph 度数有常数上界这一假设，高维下不成立。理论的通用性需要进一步分析确认。

2. **参数经验不是定理**：$m_L$、$M$、$M_{\text{max}0}$、`efConstruction` 的最优值依赖数据分布、距离函数和召回率目标。论文给出的经验值（$m_L=1/\ln(M)$, $M_{\text{max}0}=2M$）是合理的起点，但生产环境需自行扫描。

3. **分布式搜索不简单**：搜素始终从顶层单一入口点开始，简单分区无法保证吞吐量与节点数线性扩展。不过论文指出 HNSW 与 skip list 的结构相似性为分布式实现提供了思路。

4. **论文未涉及的硬件层面**：未做 chiplet、NUMA、CCD/L3、remote memory 等硬件实验。HNSW 的层次热力图（上层热、下层冷）是本文后续 chiplet 优化的出发点，但原文本身不包含相关数据。

5. **更新和删除**：论文聚焦静态数据集的增量插入。更新和删除操作、以及 1B 级别的 SIFT/DEEP 全量测试被列为后续工作。

6. **内存开销**：典型索引开销 60-450 bytes/object（不含原始向量数据），大规模索引不适合完整复制到小容量缓存。

## 与 Chiplet CPU 研究的关系

HNSW 原论文适合作为当前 HNSW 方向的**算法基础**。它定义了后续实验要控制的结构变量和查询路径：
- 入口点（entry point）
- 上层导航（layer 1..L, ef=1）
- 第 0 层 best-first search（候选队列 + 结果集）
- 邻居选择启发式

当前 chiplet 课题若要证明 HNSW 可在硬件层面优化，不能只测平均查询时间，需要在**固定 HNSW 参数、数据集、召回率目标和实现**的前提下，比较不同硬件布局方案（普通 reordering、per-CCD navigator replica、CCD owner 分区等）。

**可迁移的思路**：
- 上层导航图小而访问频繁 → 适合做 per-CCD navigator replica
- 第 0 层邻接表和向量访问决定主要访存量 → 适合做 trace-guided layout
- M、Mmax0、efConstruction、efSearch 是必须固定或系统扫描的参数
- 邻居多样化提示：chiplet-aware 布局不能只按距离放置，需保留跨簇导航边

**不能直接迁移的风险**：
- HNSW 完整索引远超单个 CCD L3 容量，不能假设"全图可复制到每个 CCD"
- 论文不证明跨 CCD 访问是瓶颈，也不证明提高 L3 命中率能转化为端到端延迟收益
- Fig. 13-15 的优势来自算法结构，不来自 chiplet 机制
