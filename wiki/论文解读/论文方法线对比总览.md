## 方法线一：任务/数据放置与本地-聚合缓存切换

### 共同判据

`CHARM`、`OLAP`、`Sorting` 和 `P-MOSS` 都把性能问题落到“执行位置”和“数据位置”的匹配关系上。前三篇直接围绕 chiplet/NUMA 内的 cache 和 coherence 开销；`P-MOSS` 不以 chiplet 为核心术语，但同样把主内存索引切成可路由、可迁移、可绑定的数据分片。

该方法线成立需要三个条件：

1. 目标 workload 存在稳定的任务或数据分片。
2. 分片的执行位置会显著改变 cache、memory 或 interconnect 访问来源。
3. 放置调整成本低于被减少的远端访问、coherence、shuffling 或迁移开销。

### CHARM

- **对象**：图计算、GUPS、SGD、OLAP、OLTP 等通用并行 workload。
- **机制**：每个 worker 读取 cache fill PMU 事件。remote cache fill 事件率超过阈值时增大 `spread_rate`，扩散到更多 chiplet；低于阈值时收紧到更少 chiplet。调度周期论文实验为 500 ms。
- **作用**：把 chiplet 局部性和聚合 L3 容量写成运行期动态决策，而不是固定 Local 或 Mixed 策略。
- **边界**：OLTP 的瓶颈是同步/提交，cache 放置无效；attention kernel 的单次调用时间远短于 CHARM 的调度周期，不能直接套用 per-kernel 调度。

### OLAP on Modern Chiplet-Based Processors

- **对象**：Presto、SingleStore、SparkSQL 等 OLAP 查询引擎 worker 部署。
- **机制**：WICP 用每 chiplet 一个独立 worker 进程切断跨 chiplet cache coherence；WICP_Local/WICP_Mixed 再按工作集是否超过单 chiplet L3 选择线程集中或分散。
- **作用**：明确两层机制：进程地址空间隔离消除 coherence，Local/Mixed 选择优化 L3 容量与延迟。
- **边界**：适合 worker 与数据 fragment 可独立部署的查询引擎；不对应 vLLM attention workitem。

### Optimizing Sorting for Chiplet-Based CPUs

- **对象**：LSB Radix-Sort 和 Comparison-Sort。
- **机制**：把 `in-cache` 拆成本地 chiplet L3 与跨 chiplet 聚合 L3；去掉 NUMA-aware 排序中的 data shuffling；用线程绑定保持跨 pass 数据局部性。
- **作用**：说明主动搬迁数据会破坏后续 pass 的局部性，跨 chiplet 数据移动本身可成为 20%-32% 级别的时间开销。
- **边界**：排序存在多轮 pass 与数据重读；attention 的 K/V 主要是 streaming 读取，复用模式不同。

### P-MOSS

- **对象**：主内存 B+-Tree index query processing。
- **机制**：按 key range 切成 `index slice`，Decision Transformer 为每个 slice 预测 worker core；slice 的 index nodes 放到该 core 本地 NUMA node；router core 按 query predicate 路由请求。
- **作用**：提供“数据分片、请求路由、core binding、NUMA page placement、PMU token”组合的软件设计。它不要求新硬件。
- **边界**：依赖稳定 key range 和可迁移 index nodes；推理/微调周期是分钟级，不适合每次 forward pass 级调度。

### 线内差异

| 维度 | CHARM | OLAP | Sorting | P-MOSS |
| --- | --- | --- | --- | --- |
| 决策方式 | PMU 动态调整 | 静态部署 + 容量启发式 | 静态/半静态 | 离线/在线学习策略 |
| 数据单位 | task 与内存范围 | worker 数据 fragment | 排序分区与 pass 数据 | index slice |
| 执行单位 | worker thread / coroutine | worker process / thread | 排序线程 | worker core |
| 关键开销 | remote cache fill | coherence 与互联拥塞 | shuffling 与远端重读 | remote memory/cache、interconnect、TLB |
| 迁移成本 | 线程/内存策略调整 | worker 部署与数据分配 | 算法流程改写 | 页面迁移，单 slice 平均 0.1 s |

## 方法线二：CPU LLM Serving 的 Phase-Aware 框架优化

### Sandwich

`Sandwich` 直接面向 CPU LLM serving。它把 prefill 和 decode 拆成不同 service configuration：prefill 优化动态 shape GEMM，decode 搜索 active core 数量、core 位置、model partition 和共享结构竞争。

可迁移点：

- prefill 与 decode 不应共用同一执行计划。
- decode 不一定适合使用所有 cores；active core 数量和物理位置会影响 memory controller、LLC tag 等共享资源竞争。
- 拓扑可抽象为 TopoTree，再用 `group` 补全潜在共享层级，用 `remove` 枚举降低竞争的 core 子集。
- model partition 与 core utilization 需要联合搜索。

边界：

- 论文收益来自 communication、service configuration、kernel tuning、split-k 等组合，不能单独归因于绑核。
- EPYC 实验平台与当前 `2 x AMD EPYC 9745 128-Core` 不同，不能直接复用 TP degree 或 core removal 策略。
- 论文没有验证当前 `kv_head` 静态 L3 局部化。

### ArcLight

`ArcLight` 面向 many-core CPU 上跨 NUMA node 的 LLM 推理。它把本地 buffer、thread group、跨 NUMA tensor parallel、Scatter/Gather 和异步子图执行联合设计。

可迁移点：

- locality 不能只依赖 OS first-touch；框架需要显式控制 tensor/buffer 放置。
- 线程组织、内存放置和计算图切分要一起设计。
- decode 与 prefill 的收益预期需要分开评估；论文中 prefill 收益小于 decode。

边界：

- 平台是 ARM Kunpeng-920，baseline 是 `llama.cpp`，不是当前 AMD EPYC + vLLM。
- 粒度是 NUMA node 和整模型图执行，不是 CCD/L3 slice 或 attention kernel 内任务分片。

## 方法线三：共享工作集驱动的拓扑映射

### GPU Attention NUMA Effects

该论文把共享同一组 K/V 的 workgroup 集合定义为 `ACC`，并通过 `Swizzled Head-first Mapping` 让同一 `ACC` 尽量落在同一 `XCD`。收益来自 K/V 在本地 L2 中的复用，而不是简单减少跨 die 通信。

对当前 CPU 路径的启发是“先识别共享工作集，再设计映射”。GPU 中的 `ACC` 可抽象对应 CPU prefill 中共享同一 `kv_head` 或共享重叠 K/V 前缀的一组任务。

## 方法线四：网络 I/O 的 Buffer Tiering

### TiNA

`TiNA` 在 Intel Sapphire Rapids SNC 模式下管理 NIC receive buffer。Local-tier DCA ways 延迟低但容量小；Remote-tier DCA ways 容量大但访问更远。TiNA-NIC 根据 active mbuf size 选择 packet 写入本地或远端 descriptor buffer，TiNA-stack 用 sequence number 保序。

它与 CHARM/OLAP/Sorting 的共同点是“本地低延迟 vs 聚合容量”的切换；差异是对象从通用 cache 工作集变成 NIC DMA 写入的 DCA ways，决策发生在网络包接收路径，时间尺度是微秒级。

边界：
- 依赖 DCA/DDIO、SNC、RSS、多 hardware queue NIC 等机制。

## 方法线五：硬件/模拟系统中的复制、迁移与分区

### MEMPLEX

`MEMPLEX` 是硬件内存系统，不是软件 runtime。它在多 chiplet NUMA + HBM/DDR 系统中把每个 HBM node 的一部分作为私有 DRAM cache，并在 DRAM cache eviction 时按访问热度与远端流量预算决定是否迁移完整 sector 到本地内存。

可迁移点：

- 远端访问需要拆成 local HBM、remote HBM、external DDR 等来源，而不是只看总 memory traffic。
- 复制与迁移应分层：cache line 级复制降低首次访问成本，sector 级迁移处理反复访问的数据。
- 迁移判据必须显式计入迁移自身产生的远端流量。

边界：

- 需要 DCC、DCTA、remap table、free memory stack 等硬件机制。
- 评估来自模拟系统和 multi-programmed workload，不是 AMD EPYC 实机或 LLM 推理。
- 不能从 MEMPLEX 推出当前软件线程绑定可实现透明 KV page 迁移。

### Effects of Poor Workload Partitioning

该论文研究 DNN inference task graph 在 chiplet accelerator 上的分区质量。核心变量是 partitioning quality：强通信任务 co-location 越好，跨 chiplet edge cut、traffic、congestion 和通信开销越低。

可迁移点：

- chiplet 优化前应先把 workload 表达为通信图：任务节点、边权、关键路径、可 co-location 的强通信边。
- 评估分区策略不能只看平均 latency，还要看 traffic share、link utilization、communication overhead、throughput 和 energy。
- chiplet 数量增加后，通信代价可能非线性放大。

边界：

- 系统是参数化 DNN accelerator simulator，不是服务器 CPU。
- 任务粒度是 DNN task/layer graph，不是 OpenMP workitem、cache line 或 CPU thread。
- 8.75x throughput、87.4% traffic reduction 等数字不能外推到 vLLM CPU 推理。

### NoC AI-Driven Mapping 综述

该综述提供 NoC application mapping 的分类：static、dynamic、hybrid、machine learning-based。它还提出 chiplet fabric 需要 `cluster -> chiplet -> PE` 的层次化映射语言。

可迁移点：

- 对大规模 chiplet/NoC 系统，离线 backbone + 在线局部 correction 通常比全局在线重排更可实施。
- 学习型映射必须检查训练成本、推理延迟、状态观测成本、故障泛化和约束满足。
- 映射方案应同时纳入 latency、throughput、bandwidth utilization、response time、fault/thermal 约束。

边界：

- 综述不提出新算法，也没有统一 benchmark 的横向实验。
- Table 2 中的收益来自不同论文，不能作为当前平台的预期收益。
- NoC 的 PE/router/link 抽象不能直接等同于 AMD EPYC CCD/L3/NUMA 绑核。

## 方法线六：硬件基线与微架构诊断

### AMD EPYC Rome 与 Intel Cascade Lake SP 内存性能

该文档提供硬件事实边界。Rome 上同 socket 内访问至少要区分 CCX 本地、同 CCD 其他 CCX、同 socket 其他 NUMA node、其他 socket NUMA node。远端 cache 或远端 NUMA 路径可接近甚至慢于本地主存访问。该差异是 chiplet-aware 方法成立的硬件前提。

对当前 EPYC 9745 平台的使用方式：不能直接复用 Rome 数值；可复用的是“先测层级延迟和来源，再决定优化粒度”的方法。

### Fake-Busy / True-Idle

该论文不提供任务放置算法。它诊断图应用在 chiplet OoO 多核上的 ROB/LQ 占用，指出部分资源占用来自等待 branch-resolving load 或被 squash 的投机指令。它提醒性能归因不能只看队列是否满，还要区分有效执行、投机占用和无效占用。

对当前课题的作用是补充微架构诊断视角。若后续 workload 是分支密集、load 依赖强的不规则应用，ROB/LQ 指标需要按有效性解释。

## 跨方法线对比

### 本地延迟与聚合容量

| 论文 | 本地域 | 聚合域 | 切换信号 | 约束 |
| --- | --- | --- | --- | --- |
| CHARM | 单 chiplet L3 | 多 chiplet 聚合 L3 | remote cache fill PMU | 500 ms 级运行期调整 |
| OLAP | WICP_Local | WICP_Mixed | 工作集 vs 单 chiplet L3 | worker 进程与数据 fragment 可独立部署 |
| Sorting | Chiplet_Local | Chiplet_Mixed | 输入规模与线程数 | 排序流程可改写 |
| TiNA | Local-tier DCA | Remote-tier DCA | active mbuf size | NIC receive path 微秒级决策 |
| Sandwich decode | 较少 active cores / 特定拓扑子集 | 更多 cores / TP 配置 | trace latency simulation | 离线 tuning 后复用 |

该模式不能简化为“越本地越好”。当工作集超过本地容量、并行度超过本地域核心数，或共享资源竞争超过计算收益时，需要扩大或改变执行域。

### 通信图与共享工作集

| 论文 | 图节点 | 边或共享对象 | 优化目标 |
| --- | --- | --- | --- |
| GPU Attention | workgroup | 共享 K/V 的 `ACC` | 提高同 XCD L2 复用 |
| Effects | DNN task | task graph communication edge | 降低 edge cut 和 NoI congestion |
| NoC 综述 | PE/task | NoC packet flow、thermal/fault 状态 | 多目标映射 |
| P-MOSS | index slice / worker core | query predicate 到 key range | 请求路由与数据本地化 |
| OLAP | worker / fragment | scan、join、repartition 数据流 | 消除 coherence 与跨 chiplet 访问 |

这条线的共同点是：先定义“谁共享数据或通信频繁”，再决定映射。没有明确通信图或共享工作集时，绑核策略容易退化为静态拓扑启发式。

### 决策机制

| 决策类型 | 代表论文 | 适用场景 | 风险 |
| --- | --- | --- | --- |
| 静态容量阈值 | Sorting、OLAP Local/Mixed | 输入规模和并行度已知 | 无法适应 workload phase 变化 |
| PMU 动态反馈 | CHARM、P-MOSS | 策略可在线调整，PMU 与瓶颈相关 | 采样、迁移、推理开销可能抵消收益 |
| 离线搜索 | Sandwich | 模型、平台、请求分布较稳定 | tuning 成本高 |
| 硬件实时决策 | TiNA、MEMPLEX | packet 或 cache miss 路径 | 依赖硬件支持 |
| 仿真/综述框架 | Effects、NoC review | 方法论筛选和设计空间分析 | 不能作为实机性能证据 |

## Chiplet 优化适用性筛选框架

### 第一筛：关键路径上的跨域访问占比

先用 PCM/PMU 或端到端 tracing 判断跨 CCD、跨 NUMA、远端 DRAM、interconnect traffic、queueing delay 是否占显著比例。若跨域访问占比极低，chiplet 放置的理论收益上限也低。

### 第二筛：瓶颈是否能被放置改变

跨域访问占比高不代表放置一定有效。需要确认访问来自“数据与处理它的线程/任务不在同一局部域”，且软件有权移动任务、数据、页面、worker、buffer 或请求路由。

### 第三筛：复用与容量敏感性

用 CAT、STREAM、工作集 sweep 或 workload phase sweep 判断目标数据是否依赖 L3/LLC/DRAM cache 复用。若数据只是 streaming 通过 L3，改善 L3 occupancy 或 L3 miss/task 可能不改变时延。

### 第四筛：并行度与调度补空能力

本地化会减少可参与执行的核心或 worker 范围。若局部化降低并行度、负载均衡或跨组补空能力，locality 收益可能被调度损失抵消。当前 `acc-local-l3` 的长序列退化属于这一类。

### 第五筛：控制面成本

不同方法的控制成本差异很大：CHARM 为 500 ms 级 PMU 调整，P-MOSS 推理/微调为分钟级，Sandwich tuning 为离线秒到小时级，TiNA/MEMPLEX 依赖硬件路径。控制周期必须匹配 workload phase 长度。

## 当前课题结论

- `acc-local-l3` 按 `kv_head` 静态限制任务领取范围，改变的是 CPU attention 内部任务分配，不改变 attention 数学计算。
- 当前实测显示该方向短中长度收益不足 1%，长序列明显慢于 `balanced`。核心原因是局部化限制降低跨分组补空能力，调度并行效率损失超过 L3 局部性收益。
- `CHARM`、`OLAP`、`Sorting`、`P-MOSS` 支持的结论是：chiplet 放置有效的前提是跨域访问或数据搬迁在关键路径上占比显著，且能被放置改变。
- `GPU Attention NUMA Effects` 支持“共享工作集驱动映射”这一抽象，但不能证明 CPU attention 的静态 L3/CCD 分组有效。
- `Sandwich` 和 `ArcLight` 指向全链路 CPU LLM serving 优化：prefill/decode 分相、model partition、core utilization、内存放置和通信实现联合设计。该方向比继续微调 attention-only `kv_head` 局部化更接近当前负结果后的可行路径。
- `MEMPLEX`、`Effects` 和 NoC 综述适合作为设计空间与判据来源，不适合作为当前 AMD EPYC + vLLM 软件可直接复现的性能依据。

## 后续扫描方向

- **CPU LLM serving 全链路**：按 Sandwich/ArcLight 的方式分开测 prefill、decode、通信、batch 拼装、线程池和内存分配。
- **可路由数据结构**：按 P-MOSS 的标准寻找稳定分片、请求可路由、页面可迁移的数据结构，例如索引、KV cache 管理或检索侧数据结构。
- **通信图明显的环节**：按 Effects/NoC 的标准寻找跨 rank、跨进程、跨 chiplet 的高流量边，再判断 co-location 是否能降低 edge cut。
- **网络/RPC/KV serving**：TiNA 的方法线只适用于网络 I/O 或服务端 packet/buffer 路径，不适用于 attention kernel。
