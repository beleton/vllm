# 论文方法线对比总览

## 分类总览
| 类别 | 论文 | 最核心思想 | 方法落点 |
| --- | --- | --- | --- |
| `Chiplet CPU` 上的缓存放置切换 | `CHARM` | 不把单 `NUMA` 域视为均匀资源；按运行期缓存/远端访问压力，在更强局部性与更大聚合 `L3` 容量之间切换 | runtime 调度、线程/内存放置、自适应扩散 |
| `Chiplet CPU` 上的缓存放置切换 | `Optimizing Sorting for Chiplet-Based CPUs` | 把 `in-cache` 进一步拆成“单 chiplet 本地 `L3`”与“跨 chiplet 聚合 `L3`”，再按数据规模选择 `Chiplet_Local` 或 `Chiplet_Mixed` | 排序分区、线程放置、避免 `shuffling` |
| 共享 `K/V` 工作集驱动的拓扑映射 | `GPU Attention NUMA Effects` | 把共享同一组 `K/V` 的 workgroup 集合定义为 `ACC`，并让同一 `ACC` 尽量落在同一 `XCD`，提升本地 `L2` 复用 | kernel 级 workgroup 映射 |
| 框架级 `NUMA` 协同设计 | `ArcLight` | 把本地 buffer、线程组和跨 `NUMA` 的 tensor parallel 联合设计，让各节点尽量在本地 shard 和本地内存上执行 | 框架内存管理、线程组织、子图执行 |
| 硬件行为基线 | `Memory Performance of AMD EPYC Rome and Intel Cascade Lake SP Server Processors` | 先测清 `CCX/NUMA/socket` 各层的延迟与带宽差异，说明 chiplet CPU 上“同 socket”并不等于均匀共享域 | 硬件测量，不是优化算法 |

## 第一类：`CHARM` 与 `Optimizing Sorting`
- 共同点：两篇都把核心问题写成“局部性”和“聚合缓存容量”的取舍，不把“尽量收紧到更小局部域”当成固定最优。
- `CHARM`：用 PMU 驱动 `spread_rate` 调整；工作集压力高时扩散到更多 chiplet，压力低时收紧到更少 chiplet。
- `Optimizing Sorting`：直接按数据规模相对单 chiplet / 聚合 `L3` 容量来选 `Chiplet_Local` 或 `Chiplet_Mixed`，并通过去 `shuffling` 降低跨 chiplet 代价。
- 差异：`CHARM` 是通用 runtime；排序论文是面向排序管线的静态/半静态策略。

## 第二类：`GPU Attention NUMA Effects`
- 核心不是切换“本地 vs 聚合缓存”，而是先识别谁真正共享同一份 `K/V`。
- 论文把这个共享单元定义为 `ACC`，再用 `Swizzled Head-first Mapping` 让同一 `ACC` 尽量收敛到同一 `XCD`。
- 这条方法线更接近“共享工作集驱动的拓扑映射”，研究粒度是 attention kernel，而不是通用 runtime。

## 第三类：`ArcLight`
- `ArcLight` 的重点不是 kernel 映射，而是整框架的 `NUMA-aware` 协同设计。
- 它把 buffer 放置、线程组拆分/合并、跨 `NUMA` tensor parallel 和异步子图执行绑在一起，目标是减少跨节点远端 DRAM 访问。
- 与前两类相比，它优化的是框架执行路径，不是 `L3` 粒度的任务映射。

## 背景类：`Rome/CLX` 内存性能论文
- 这篇论文不提供调度或映射方法，作用是给出硬件事实边界。
- 它说明在 `Rome` 上至少要区分 `CCX` 本地、同 socket 远端 `CCX/NUMA`、其他 socket 等不同访问层级；这类差异正是前述 chiplet-aware 方法成立的硬件前提。

## 可直接提炼的总判断
- `CHARM` 与排序论文属于同一条方法线：按工作集大小或运行期访存压力，在“更强局部性”与“更大聚合缓存”之间切换。
- `GPU Attention NUMA Effects` 属于另一条方法线：把共享 `K/V` 工作集本身当作放置单元，优先优化映射而不是先改算子数学。
- `ArcLight` 更适合作为框架级 `NUMA` 设计参考，不直接回答 `CCX/L3` 粒度下的 kernel 放置问题。
- `Rome/CLX` 内存性能论文更适合作为硬件背景，不宜与前述优化论文并列解读为同类方法。
