# 2026-03-30 下一步研究计划

## 文档定位
- 这页保留 `2026-03-30` 当时的阶段计划，但已按当前实际执行情况补上状态更新。
- 当前状态更新只基于已经落地的结果页与源码说明页，不补新推测。

## 当时的证据基线
- `Prefill/Decode` 分相结果已经证明：在 `B16/I1024/O1` 与 `B16/I1/O1024` 这组负载下，decode 的 `L3 Miss %` 和 `Ave L3 Miss Latency` 明显高于 prefill。
- decode 长度 sweep 已显示一个稳定现象：`O64/O128/O256/O512/O1024` 下，`L3 Miss %` 长时间维持在约 `96%`，`Ave L3 Miss Latency` 维持在约 `326-328 ns`。
- prefill 长度 sweep 则不是平的：`I128/I512/I1024` 的 `L3 Miss %` 分别为 `8.82/14.55/49.43`，`same-node another CCX %` 分别为 `25.42/11.65/2.91`。
- 源码侧已有静态证据说明：prefill attention 中，同一 `kv_head` 会被拆成多个线程任务，且不同线程可能读取高度重叠的 KV 前缀。
- 当时还没有函数级证据证明 decode 的高 `L3 miss` 主要来自 attention，而不是 `MoE/MLP`、`TP all_reduce` 或其他路径。

## 当时的判断边界
- 不应把 `Prefill/Decode` 的 `L3 Miss` 差异直接写成“Chiplet CPU 独有现象”。
- 更合理的问题应是：`Prefill/Decode` 的 phase gap 中，哪些部分会随 `CCD/CCX/NUMA` 放置显著变化，哪些只是通用工作集或容量 miss。
- 仅凭 `Remote DRAM Reads %` 很低，不能把 decode 的高 miss 直接归因到远端 DRAM。
- 仅凭某个 prefill 长度点的 `same-node another CCX %` 偏高，也不能写成稳定规律。

## 当时给出的阶段目标
1. 先补齐 `Prefill/Decode` 的函数级归因，确认高 `L3 miss` 主要落在哪条调用链。
2. 若 attention 确实是主贡献者，再建立更贴近真实 `block_table/slot_mapping/query_start_loc/seq_lens` 的 attention 试验台。
3. 只有在前两步都成立时，才进入 `NPS`、`TP`、线程绑核和 NUMA 内存策略的系统级优化实验。

- 当前可落的结论：
  - 当前证据不支持把 decode 的高 `L3 miss` 直接写成“显式 attention 包装层主导”
  - decode 的过滤后 miss 延迟主要还是本地 DRAM 路径，不是远端 DRAM 主导
  - prefill 的 miss 主路径比 decode 更靠近 `vLLM` 原生路径，已经能看到 `attention/KV-cache` 与 `TP SHM` 通信痕迹
  - prefill 不是“只有 attention”或“只有 MoE”；更像 `TP SHM 通信 + 通用 GEMM + MoE + attention/KV-cache` 共同出现在 miss 主路径里
- 对后续计划的影响：
  - “先做函数级归因再决定是否继续 attention 主线”这一步已经完成
  - 后续不能再把 `P0` 写成待办项

### P3：从“纯系统级拓扑实验”改成“先实现并验证 locality-aware kernel”
- 状态：已启动并已有实现结果
- 这一步已不再只是 `NPS/TP/绑核/NUMA` 的大矩阵实验计划。
- 当前实际已经参考 `Optimizing Attention on GPUs by Exploiting GPU Architectural NUMA Effects` 的思路，实现了 CPU attention `acc-local-l3` 新 kernel。
- 结果入口：
  - [CPU_attention_acc_locality新kernel实现说明.md](../源码分析/CPU_attention_acc_locality新kernel实现说明.md)
  - [2026-04-05_Qwen3-30B-A3B_P3_AttnOnly_acc-local-l3对照观察.md](../实验结果解读/2026-04-05_Qwen3-30B-A3B_P3_AttnOnly_acc-local-l3对照观察.md)
- 当前可落的结论：
  - 这次实现不是直接改 legacy `cpu_attention_with_kv_cache`，而是在旁边新增 `acc-local-l3` 路径
  - 新路径已实现 `L3/CCX` 分组、`kv_head -> subgroup` 映射和 subgroup 内线程过滤
  - `acc-local-l3` 已经在首轮对照里表现出 locality 变化，但当前还不能写成“性能已证优”
- 因此，`P3` 当前更准确的定义应改成：
  - 先把 locality-aware kernel 的实现边界、适用长度区间和性能代价搞清楚
  - 再决定是否继续扩大到系统级拓扑矩阵
