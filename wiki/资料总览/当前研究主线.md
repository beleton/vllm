# 当前研究主线

## 课题与平台

在 Chiplet CPU（`2 x AMD EPYC 9745 128-Core`，每 CPU 8 个 CCD，每 16 核共享约 32 MiB 本地 L3）上，利用 vLLM 框架研究如何结合分片 L3/CCD 架构特征优化 CPU LLM 推理。目标是形成论文产出。

## 方法启发

- **CHARM**：Chiplet CPU 上存在"局部性"和"聚合缓存容量"的权衡，可借鉴其按工作集大小在 LocalCache 与 DistributedCache 之间切换的调度思路。
- **GPU NUMA Attention 论文**：将共享同一组 K/V 的 workgroup 映射到同一拓扑域以提高 cache reuse，方法论可映射到 CPU prefill 场景。

## ACC-local-L3 尝试与结论

基于"共享 KV 工作集 → 局部域放置"的思路，实现了 `acc-local-l3` kernel：按本地 L3/CCD 将线程分组，每个 `kv_head` 只开放给指定分组执行，不改变 attention 数学计算，只改变任务领取范围。

**结论：该方向不可行。** 实测显示 `acc-local-l3` 在短中长度上有小幅收益（<1%），但长序列下明显慢于 `balanced`（+6%~+32%）。核心矛盾是：限制 `kv_head` 执行范围会降低跨分组补空能力，局部性收益被调度并行效率损失抵消。详细数据见 [ACC-local-L3尝试分析](./ACC-local-L3尝试分析.md)。

## 当前状态

- **已确认**：Chiplet CPU 上跨 CCD 访问代价接近本地内存（约 110~150 ns vs 120 ns），低延迟共享域更接近本地 L3/CCD。
- **已确认**：prefill 与 decode 的 L3 行为不同。decode 的高 L3 Miss 更像本地内存路径上的容量/流式 miss，不是跨 CCD 主导；prefill 随长度变化发生来源切换，短中长度更适合尝试拓扑感知优化。
- **已排除**：按 `kv_head` 做静态 L3 局部化不是有效路径——它改变了 locality 指标但无法转化为稳定时延收益。
- **待定**：下一步方向仍在讨论中。
