# Attention ACC 实现进展汇报

## 研究目标

当前工作关注 vLLM CPU attention 在 Chiplet CPU 上的 `K/V` 访问局部性。Chiplet CPU 的核心被分布在多个 `CCD/CCX` 上，每个局部域有独立的本地 `L3`。如果同一份 `K/V` 被多个 `CCD` 反复读取，会产生缓存副本、跨 `CCD` 补线和本地 `L3` 容量竞争。

ACC（Attention Computation Cluster，注意力计算集群）在这里指共享同一组 `K/V` 的 attention 任务集合。当前实现的目标是把这些任务尽量限制在同一个本地 `L3` 局部域内执行，减少同一 `K/V` 在多个 `CCD` 之间扩散。

## CPU attention 的任务结构

CPU attention 不会一次性把整个 attention 矩阵算完，而是先切成多个 `workitem`。每个线程领取一个任务后，会在任务内部继续切分 `q_tile` 和 `kv_tile`，再执行 attention 计算。

直观流程如下：

```text
for each workitem:
  确定本次要计算的 kv_head 和 q 范围
  for each q_tile:
    for each kv_tile:
      计算当前 q_tile 对当前 kv_tile 的 attention
```

`q_tile` 是 query 方向的小块，`kv_tile` 是当前可见 `K/V` 前缀的小块。在 prefill（提示预填充）场景下，后续 `q_tile` 会继续访问前面的 `K/V` 前缀。因此，同一个 `workitem` 内会多次访问相同或重叠的 `K/V` 数据。如果这些 `K/V` 能留在本地 `L3`，后续访问可以从本地缓存获得；如果被挤出，则需要从其他 `CCD` 或内存重新获取。

## balanced 调度的问题

vLLM 原有 `balanced` 策略采用全局抢任务方式。所有线程共享一个任务池，谁先空闲就领取下一个任务。这种策略优先保证线程负载均衡，但不保证 `kv_head` 与本地 `L3` 的绑定关系。

其结果是：

- 同一个 `kv_head` 的任务可能被多个 `CCD` 上的线程计算。
- 同一个 `CCD` 可能同时处理多个不同 `kv_head`。
- 多个 `kv_head` 的 `K/V` 同时进入同一个本地 `L3` 后，会增加容量竞争。
- 当单个 `kv_head` 的 `K/V` 仍可能留在 `L3`，但多个 `kv_head` 的聚合工作集超过本地 `L3` 时，`balanced` 更容易丢失 `K/V` 复用机会。

## ACC-local-L3 的实现思路

当前 `acc-local-l3` 没有改变 attention 的数学计算过程，也没有重写 tile 计算、softmax 或 reduction。它主要改变任务领取范围。

实现思路分三步：

1. 先按硬件局部性把线程分组。一个分组对应一个本地 `L3/CCD` 局部域。
2. 再把每个 `kv_head` 分配给一个或多个连续分组。
3. 线程只能领取自己所在分组覆盖到的 `kv_head` 任务。

简化后的对比如下：

```text
balanced:
  所有线程共享一个全局任务池
  任意线程都可以领取任意 kv_head 的任务

acc-local-l3:
  线程先归属到本地 L3 分组
  每个 kv_head 只开放给指定分组
  分组内部线程动态领取该 kv_head 的任务
```

`acc-local-l3` 不是静态地把每个任务固定给某个线程。它仍保留分组内部的动态领取机制：同一个 `kv_head` 的任务由覆盖它的本地线程池共同领取，避免同一任务被重复执行，同时把 `K/V` 访问范围限制在更小的本地 `L3` 范围内。

在当前常用的 `qhead=32 / kvhead=16 / TP=2 / group_span=1` 实验配置下，每个 rank 有 `8` 个本地 `kv_head`，机器上每个 rank 可见 `8` 个本地 `L3` 分组。因此可近似理解为：每个本地 `kv_head` 固定到一个本地 `L3` 分组上执行。

## 理论预期

以 `head_dim=128`、`bf16` 为例，单个 `kv_head` 的 `K+V` 数据量为：

```text
K + V = 2 × 128 × 2 B = 512 B / token
```

一个约 `32 MiB` 的本地 `L3` 理论上可容纳约 `65,536` token 的单 `kv_head` K/V。实际可用容量会低于该值，因为还存在 `Q`、中间结果、元数据、scratchpad、其他线程数据和缓存碎片。

理论上，`acc-local-l3` 的收益窗口出现在以下条件同时成立时：

- 同一个 `kv_head` 的 `K/V` 会被多个 `q_tile` 重复访问。
- 单个 `kv_head` 的 `K/V` 仍有机会在本地 `L3` 中复用。
- 多个 `kv_head` 聚合后会造成同一 `L3` 容量竞争。
- 限制 `kv_head` 的执行范围不会明显降低线程并行度。

在这些条件下，`acc-local-l3` 应减少跨 `CCD` 扩散和本地 `L3` 争用，从而降低 attention 时延。

## 当前实测现象

最新 attention-only 对照实验使用 `NPS1_TP2 / prefill-like / global-fixed / batch=1 / qhead=32 / kvhead=16 / group_span=1`。`acc-local-l3` 只在中短长度上有小幅收益，在更长长度上明显慢于 `balanced`。

| q=kv | balanced 最慢 rank 平均时延 | acc-local-l3 最慢 rank 平均时延 | acc 相对变化 |
| ---: | ---: | ---: | ---: |
| 256 | 0.055 ms | 0.054 ms | -3.09% |
| 512 | 0.119 ms | 0.118 ms | -0.96% |
| 1024 | 0.374 ms | 0.371 ms | -0.62% |
| 2048 | 1.414 ms | 1.873 ms | +32.49% |
| 4096 | 6.631 ms | 7.798 ms | +17.61% |
| 8192 | 29.634 ms | 32.847 ms | +10.84% |
| 16384 | 126.621 ms | 138.038 ms | +9.02% |
| 32768 | 516.573 ms | 564.512 ms | +9.28% |
| 65536 | 2112.045 ms | 2251.869 ms | +6.62% |

同一批数据中，`acc-local-l3` 经常能降低部分局部性相关指标，例如 `L3 Access (pti)` 和跨 `CCD` demand fill（按需补线）。但这些改善没有稳定转化为端到端时延收益。典型现象是：`q=2048/4096` 时，`acc-local-l3` 的 `L3 Access (pti)` 低于 `balanced`，跨 `CCD` demand fill 也更低，但整体时延分别变慢 `32.49%` 和 `17.61%`。

性能 profile（性能剖析）还显示，长序列下 `acc-local-l3` 的有效并行度下降。以最慢 rank（张量并行子进程）的 attention 有效线程数为例：

| q=kv | balanced | acc-local-l3 |
| ---: | ---: | ---: |
| 2048 | 97.43 | 76.03 |
| 4096 | 86.85 | 74.11 |
| 8192 | 78.95 | 71.27 |
| 16384 | 77.57 | 71.63 |

这说明当前实测瓶颈不只是 `K/V` 是否更靠近本地 `L3`，还包括任务调度带来的线程利用率变化。

## 理论与实测差距

理论分析主要抓住了 `K/V` 复用和本地 `L3` 容量两个因素，假设把同一 `kv_head` 限制在同一个本地 `L3` 后，减少的数据搬移能直接转化为时延收益。实测表明这个假设不完整。

当前差距主要来自三点：

1. `acc-local-l3` 限制了跨分组抢任务能力。`balanced` 可以让空闲线程继续领取其他 `kv_head` 的任务，而 `acc-local-l3` 只能在本地分组覆盖范围内补空。长序列下单个任务成本更不均匀时，这会降低有效并行度。
2. 局部性收益和并行度损失同时存在。`acc-local-l3` 可以减少部分跨 `CCD` 访问，但如果线程等待、负载不均或局部任务池耗尽带来的损失更大，最终时延仍会变慢。
3. 长序列下瓶颈不再只由本地 `L3` 决定。随着 `K/V` 工作集继续增大，访问来源会更多转向本地内存，单纯把 `kv_head` 收紧到一个 `L3` 分组内，不能保证继续获得收益。

因此，当前结果不能写成“ACC 已经稳定提升 attention 性能”。更准确的阶段判断是：`acc-local-l3` 已经实现了按本地 `L3` 约束 `kv_head` 执行范围的机制，并且能改变部分 cache/locality 指标；但端到端性能仍不稳定，主要矛盾正在从单纯的 `K/V` 局部性转向“局部性收益与调度并行效率之间的权衡”。

## 阶段结论

当前 ACC 实现已经完成了核心调度机制：按本地 `L3` 对线程分组，并把 `kv_head` 的 attention 任务限制在对应分组内执行。该实现保留原 attention 计算流程，只改变任务领取范围。

实测结果显示，ACC 在部分中短长度上有小幅收益，但在长序列上仍慢于 `balanced`。现有数据支持“ACC 改善了部分 locality 指标”，但不支持“locality 改善必然带来时延收益”。后续优化重点应放在局部分组内的负载均衡、跨分组补空机制，以及不同长度下 locality 与并行度的切换策略。

## 下一步计划

下一步按 L3 驻留验证实验继续确认 `K/V` 数据是否实际留在本地 `L3`。优先计算 `L3 Miss / attention task`，判断 `acc-local-l3` 是否减少每个 attention 任务的 L3 miss；再用 `resctrl` 观察 `LLC occupancy`，确认不同模式下本地 `L3` 占用是否符合工作集预期。

随后用 `CAT` 做本地 `L3` 容量限制，观察 `acc-local-l3` 对 L3 容量变化是否敏感。最后用 `IBS L3-miss` 查看 miss 来源和函数调用链，区分“没有形成 L3 驻留”和“形成了驻留但未落到关键路径”两种情况。
